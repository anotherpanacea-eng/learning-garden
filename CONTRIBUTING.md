# Contributing to The Learning Garden

Use generic, fictional examples and synthetic test observations. Keep real child or family information out of source, tests, fixtures, lesson packs, documentation, comments, commit messages, screenshots, issues, and pull requests. This includes names and nicknames, ages or grades associated with a child, schools, locations, family stories, responses, progress, photos, audio, and device identifiers.

Keep personalized packs and records outside the checkout or in ignored local directories. Ignore rules reduce accidental staging; inspect the actual staged files before every public push. Do not paste learner exports into public issues or AI prompts as part of a contribution.

Use a GitHub no-reply email for public commits. Keep secrets, access tokens, deployment account IDs, and existing deployment configuration out of the repository. Use placeholders in any future examples.

Preserve the distinctions between independent reasoning, counting, support, retries, skips, and unobserved skills. Describe evidence from individual tasks and keep interesting activities accessible. No timer or score is needed to make an activity worthwhile.

Run the three commands under "Check the existing learning logic" in README.md when changing the relevant logic. Test the changed interaction in a browser when changing the UI.

Preserve attribution and the separate licenses for Marble-derived curriculum data. When incorporating external code, record its source and license. The initial app has no runtime dependency on Jane.
