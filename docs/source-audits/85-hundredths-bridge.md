# Hundredths Bridge: bounded source audit

Prepared 2026-10-22 for [spec 85](../specs/85-hundredths-bridge.md). These are source and design comparisons, not incorporated lesson text, independent learner evidence, or complete curriculum coverage. Public source snapshots were fetched into a temporary review directory, outside this repository.

## Primary standard and existing app overlap

- [Common Core 4.NF.C.6](https://www.thecorestandards.org/Math/Content/4/NF/C/6/) explicitly connects decimal notation with fractions of denominator 10 or 100. The bridge's `0.3 = 0.30` and 35/100 pictures are a partial model of that connection. It does not teach arbitrary conversions, lengths, or number-line placement.
- [Common Core 4.NF.C.7](https://www.thecorestandards.org/Math/Content/4/NF/C/7/) says comparisons to hundredths require reasoning about size and the **same whole**, with visual justification as an example. The pack uses one fixed-size whole and three supplied comparisons. It does not show independent comparison across arbitrary decimals or fulfill the entire standard.
- [Spec 81 and its source audit](../source-audits/81-tenths-table.md) already cover a fixed ten-part strip, `0.4`/4/10 and 0/10–10/10. Fraction Trail uses a 12-tick length whole, and Same Amount, New Cuts uses specified partitions of that ribbon. Neither supplies a 10×10 area whole, hundredth moves, or same-whole decimal comparisons. Reusing their numeric model directly would change the unit. The new bridge should keep its source/check pattern, not their answer keys or catalog validator.

## Reuse decision

The current Tenths Table source, help/check/keep convention, actual-report preflight, and existing whole-number fact-exposure hook are the local implementation references. Its version-1 ten-cell state cannot safely host 100-part cases without mixed render/validation paths. A separate optional root is bounded to this finite pack and leaves old saves byte-compatible. The 10×10 board and comparisons are original, with no imported source art. This does not create a general decimal framework or claim that pictured practice is independent knowledge.
