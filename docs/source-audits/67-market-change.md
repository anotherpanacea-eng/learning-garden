## Official denomination support and bounded cases

Freshly opened [CFPB Learning about coins](https://www.consumerfinance.gov/consumer-tools/educator-tool/youth-financial-education/teach/activities/learning-about-coins/) and its [teacher guide](https://files.consumerfinance.gov/f/documents/cfpb_building_block_activities_learning-about-coins_guide.pdf), page2, support penny1¢, nickel5¢, dime10¢ and quarter25¢. The guide dates from2022; it is used for denomination values, not as evidence of a learning effect. The [US Mint specification table](https://www.usmint.gov/learn/coins-and-medals/circulating-coins/coin-specifications) was also freshly opened. No production, legal-tender availability, till-stock, cash-rounding or current circulation claim is needed. No official coin images, worksheets, portraits, prose or layout are copied. Local schematic coins already supply labelled values and cent dots; a coin's size or number is not its monetary value.

These six cases are source-supported candidate content, not specification approval. For adequate tender the central relation is **price + returned value = tendered value**. Tender, price and returned money must remain separately labelled. Selecting the returned coins is a different action from building a payment equal to the price. A helpful inverse view is to retain the price part and return the remainder, or count on from price to tender. Do not require one method or one coin composition.

For insufficient tender, report what is missing separately: no nonnegative returned vector can repair underpayment. Zero returned coins cannot make5¢ pay a6¢ price. Do not create negative coins, silently increase tender, accept any positive returned amount, or record an invented zero-change success. The spec must decide the explicit insufficient-payment response and feedback before build. Empty/unchecked drafts and an explicitly checked exact-zero answer must remain distinguishable. No shortest/fewest-coins award, required A/B difference, exact click path or prose keyword grading follows from the reference.

## Existing capability, genuine new lesson and integration limits

Inspected `dist/coin-counter-content.mjs`, `coin-counter-core.mjs`, `coin-counter-ui.mjs`, `workshop-ui.mjs`, [spec57](../specs/57-market-day-coin-counter.md), `docs/curriculum-gaps.md`, `docs/curriculum-spirals.md` and `docs/strand-map.md`. Existing pages are `coins`, `make`, `compare`; eight fixed prices range5–25¢. Existing exchange pairs preserve value while changing coin count. The roadmap explicitly defers change and budgeting as separate reviewed increments.

Current A and B are **alternative payments of the same price**. `checkCoinPayments` checks each below/exact/above and fulfills only when both are exact and compositions differ. Neither mat is tender minus price or money returned. Reinterpreting either existing mat/check would change old records' meaning. New work must retain that original loop and give returned money its own explicit meaning and records, with supplied source price/tender frozen. A learner can revise returned coins and compare an earlier check without changing that check's source/outcome. Do not retrospectively regrade prior coin work.

The useful pure local helpers are `emptyCoins`, `coinCount`, `coinTotal`, `validCoins` and `exchangeResult`. Existing validation permits each denomination count0–25, overall coin count≤25 and total≤50¢, including the empty vector; all proposed return compositions fit. Mutators `adjustCoin`/`exchangeCoins` currently target selected old A/B state and cannot automatically operate a new returned-money record. UI coin pictures, labelled totals, cent dots, add/remove and reversible exchange controls are useful local reuse; they are not an exported generic change UI. The Workshop already dispatches `coins`; a reviewed explicit Coin Counter extension can use that seam without creating an economy engine.

The missing intermediate lesson is deciding **whether tender covers price, then which value comes back**, while preserving total value between the retained price and returned part. Existing payment equivalence supplies denomination knowledge but never poses that unknown. Keep fixed tender read-only for these cases so changing the question cannot masquerade as solving it. All permitted equivalent returns should work; optional support and familiarity stay separate from the observed response. No real shop, transaction, dollar conversion, tax, rate, budget, inventory constraint, Café-stock coupling or physical cash-handling attainment is claimed.
