# 108 · Grown-up learning atlas source and reuse audit

This proposal adds an interface to already-pinned source and already-declared local encounters. No new curriculum mapping, task content, topic pin, learner evidence, or license is introduced.

At base `0e64595`, `node scripts/build-learning-atlas.mjs --check` verifies 1,590 unique topics, 3,221 acyclic source edges, eight subjects, 54 subject/domain pairs, and the scoped references and linked-topic totals reported by the generator. Reference totals are intentionally not frozen in the spec. The child-facing `dist/marble-map.json` remains 87 topics and 92 relationships. The complete originals are `curriculum/marble/topics.json` and `dependencies.json`, pinned to Marble `96a7933754af672e1bfdbf7ecb05c325860c6e0d`; the authored declaration source is `curriculum/atlas.json` plus the builder's existing `dist/broad-content.mjs` and `dist/learning-invitations.mjs` imports. A later reviewed mapping update can change reference counts without changing this interface's source boundary.

Actual reused seams: `dist/broad-ui.mjs:learningMap` owns the small child map and local observation display; the new route does not enlarge or replace it. `dist/app.mjs` owns hash routing, lazy route rendering and Grown-up notes; the new branch can load the compact catalog only on `#atlas`. The offline builder already validates IDs, edge direction/strength, subject/domain keys, reference kinds, scopes, source-file presence and route-string presence and produces the CSV/Markdown. Extending this one builder with a compact runtime output avoids a second mapping registry. `atlas.games.status` and older generated roadmap prose are snapshots, not verified deployment claims. A route shown as an active link must resolve in the current build.

Source meaning and rights: an edge is `topicId` depending on `prerequisiteId`; `hard`/`soft` are **source** designations. Their names, relationship database, and attribution remain Marble material: [pinned repository](https://github.com/withmarbleapp/os-taxonomy/tree/96a7933754af672e1bfdbf7ecb05c325860c6e0d), [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), and [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). See [NOTICE](../../NOTICE) and [curriculum README](../../curriculum/README.md). The viewer uses only source topic titles/IDs/subject/domain and direct edge strength; it preserves exact pinned source titles, including any age suffix, without shipping separate age-range fields or using those titles for placement/access; it does not reproduce unreviewed descriptions, evidence, prompts, age ranges, standards text or edge reasons as guidance. Some source statements require qualification in specific teaching contexts; a catalog link does not endorse them as a lesson. Project-authored reference scopes remain visibly separate. “No declared activity link” is not “nothing teaches this” and neither a relation nor a click is learner evidence.

Jane's pinned lesson-pack conventions in [upstream opportunities](../upstream-opportunities.md) concern task stages and revisiting ideas, not this catalog's navigation. No Jane code, prose, data, media or learner model is incorporated by this increment. The small map's own-source observation display remains a different route; the full catalog is deliberately independent of child progress.

Scope estimate for a later build: one extra derived JSON output from the existing builder (topic names/IDs/subject/domain, edge endpoints/strength, current reference scopes/routes), one lazily loaded route module and small stylesheet, two adult-entry links, and focused data/browser checks. The compact topic+edge+manual-reference projection measured about 470 KB of uncompressed JSON at this pin; dynamic check-in/place declarations add modest size. Measure the actual output before claiming a final size. No network service, graph-layout library, saved-state schema, new declarative registry, or full-course dashboard is justified.

Reviewable candidate files are the specification and original HTML design sample. Screenshots and the bounded render receipt belong in the dated run packet; they demonstrate the proposed layout only. No runtime file, source pin, declaration, learner save, generated CSV or generated authoring atlas is changed by this spec-only increment. Deployment remains deferred.
