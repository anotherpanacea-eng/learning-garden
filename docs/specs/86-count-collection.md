# 86 · My Count Collection: make data, then draw it

**Status: author draft for independent specification review.** No runtime or release is authorized by this document.

## Purpose and reuse

The existing Field Notebook charts supplied seedling measurements. Its fixed observations and scientific source must remain unchanged. Add an optional **My Count Collection** page at `#living/collection`, linked from the Living Garden and Field Notebook. The child makes a small **imaginary button collection**, records it in a table, draws bars, and reads the chart. This is a first learner-created model dataset, not a survey, verified physical observation, organism classification or full statistics lesson. A short story invitation gives it a purpose: **“The mending table is getting ready for the lantern walk. Make a pretend button collection, then leave a chart so another helper can see what is here.”** No person, location, date, private note, photograph or microphone input is needed. Real objects are optional conversation, never required or recorded.

Reuse the Field Notebook's contrast between a source and a chart draft, native input/button patterns and static bar-chart presentation where suitable. Its validator requires specific supplied observation IDs and cannot accept a made-up collection without mislabeling the origin. Use a small separate optional record, not a generic data platform or changes to the seedling catalog. Study [the source audit](../source-audits/86-count-collection.md) before building.

## Three short turns, all open

1. **Make a collection.** The source says **“Our make-believe button collection. Each picture stands for one button.”** Three categories are **Round buttons**, **Square buttons**, and **Triangular buttons**, with different outlined shapes, text and patterns. Large Add/Remove controls change each count by one, from 0 through 12; no drag, inventory cost or timer. Draw every token, in stable rows of at most six. Empty is visibly **0**, not missing. Start creates zero counts; a child can chart an empty collection. Nothing purports to be found in the real garden. The prompt is **“What will be in your collection?”** Counts and category labels remain available across turns.
2. **Make a table and chart.** Keep the source pictures available in a compact disclosure. For each category provide a labeled raw table input, blank initially, then large bar-length Add/Remove controls, initially zero. A blank table value is not zero. Whole-number table values 0–12 are usable; keep blank or invalid raw input visible with a specific notice and let the child revise or move on. The chart has a common zero baseline, equal category spacing, title **“Our button chart”**, quantity label **“Number of buttons”**, and separate non-touching bars. Show two tick-label choices, **Count by ones** and **Count by twos**. The physical 0–12 axis and bar length for a value stay the same; only labeled ticks/grid lines change. A value of 3 stays halfway between 2 and 4 in the second view, never rounded or snapped to 4. Endpoint values may be visible; this is supplied-picture practice, not independent graph decoding.
3. **Read and compare.** Ask **“In your chart, are there more round buttons, more square buttons, or the same number?”**, then optionally **“How many more, or 0 if the bars are equal?”** For the new source, use three choices in stable order Round / Same / Square. For any readable saved source, derive that prompt and the two named choices from its first two frozen categories, keeping the equality choice in the middle; compare their own bars by saved IDs, never today’s category positions. If a saved source has only one category, keep all collection/table/chart work available and replace this two-category question with **“This version has one category. You can keep its chart, or start a separate collection to compare categories.”** Do not manufacture a second category or discard its earlier reading record. The underlying collection can make any of these fit; never choose an answer by color. A raw difference input may be left blank. Checking the reading compares it with the child's **current chart bars**, even if those differ from the collection. Separately report whether the table and bars agree with the pictured collection. Do not grade a correct reading of an inaccurate chart as wrong reading, or describe that chart as faithful to its source.

Previous/Next and **Back to Field Notebook** stay open. No check, table completion or fitting bar is needed to navigate. One current turn fills the main card; source, help and earlier checks fold away. Use visible prompts that name the current object: source collection, table draft or chart. This is one repeatable loop with child-chosen counts, not a finite quiz list. Changing counts supplies a new dataset; it does not generate a new story or certify a skill.

## Checks, revision and kept work

**Check our representation** reports each table entry versus its pictured count and each bar versus that count, with missing/invalid entries described separately. **Read this chart** checks the optional comparison/difference against current bar values and states the values it read. It also displays source agreement as a separate observation. Neither action changes the collection, table or bars. A missing response is unobserved, not failure. Feedback uses neutral specifics: **“Your round bar is 4. The collection has 3 round buttons. You can change either draft or keep this version.”** No grade, score, inferred level or automatic correction.

Each explicit check snapshots its own source labels/counts, table raw values, bar values/scale, response, support and exact feedback/results. Later source, table, bar or response edits clear only live feedback. Earlier checks remain under **Latest four checks**, labeled as earlier versions, and never appear as the current verdict. New checks roll the oldest readable check out of that disclosed recent window. Preserve unreadable sibling payloads in place; summarize their count without rendering arbitrary raw data. An optional **Keep this version** stores one complete copied source/table/chart/response and latest applicable feedback; later revisions/check rollover never change the kept copy. Keeping incomplete work is welcome. It is not completion. Replacing that one kept copy is explicit and labeled **Replace our kept version**.

Optional help explains one picture = one button, a common zero, and the distinction between a table/bar/source. Opening it, asking for narration, or selecting **We worked together** records sticky support. Feedback supplies shown values; all checks are pictured model practice and do not become baseline evidence, independent data-collection evidence or adaptive input elsewhere. This first unit does not display multiplication equations or grouped multiplication arrays; no broad fact-exposure call is justified. A later scale/unit or multiplication bridge requires its own explicit display audit.

## Saved boundary and actual integration

Use optional `countCollection`, absent until **Start our collection**. It holds version 1, the copied source, current page `collect|chart|read`, table raw strings, bar integer values, scale `1|2`, raw reading response, sticky support, monotonic next check ID, recent checks and one kept copy or null. The source has a nonblank bounded title, fixed unit code `buttons`, and 1–4 uniquely identified category records with escaped labels, one of the known shape codes, and integer counts 0–12. The new authored source has the exact three categories above, but load must not require today's IDs, count, order or wording. IDs use `^[a-z][a-z0-9-]{0,63}$`; source labels/title are at most 160 UTF-8 bytes, total source at most 4 KiB; raw numeric strings at most 16 characters; feedback strings at most 2 KiB. Preserve unknown harmless keys. No current catalog equality check or load-time result recomputation. Validate saved counts/outcomes against the saved snapshot's own values, never today's source text or feedback wording.

Readable versions preserve partial inputs, zero, odd bars on a two-step axis, page, current response, support and kept work through reload, explorer switch, save-off and actual notes import/export. One malformed check/kept copy is unavailable but stays raw while the rest of the collection works; no silent deletion or replacement. A malformed/future root or source has a short isolated recovery page with Back, Download notes and confirmed **Start a separate collection**. Recovery retains the entire previous root, including earlier raw recovery; no nesting beyond actual import limits and no new archive registry.

New Start, check append, Keep and recovery preflight the complete proposed notebook and the actual formatted `notesReport` used by Download through existing import/size/depth/node limits. Refusal is atomic, preserves the original and gives an actionable download/separate-explorer notice. Ordinary finite edits use existing visible quota-failure handling and keep in-memory work/download available. Add the optional raw root to the existing importer/notes routing without weakening unrelated roots. Nothing changes Field Notebook, Plant Study, garden ingredients or café stock.
