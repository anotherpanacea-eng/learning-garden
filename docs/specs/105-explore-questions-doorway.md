# 105 · Questions to follow: a smaller Explore doorway

**Status:** original specification for independent review; no runtime change yet. **Home:** `#explore`. **Source audit:** [105](../source-audits/105-explore-questions-doorway.md). **Visual proposal:** [interactive mock](assets/105-explore-questions-doorway.html). This is navigation and authored connective copy, not a new lesson, learner model, assessment, or curriculum-map declaration.

## Why this change

At 320 CSS px, the current `#explore` has twelve stacked place cards and a 4,734 px page. Each place uses the same “Explore this place” action. The places are real and should remain reachable, but a child has to scroll a long directory and translate place names into a reason to visit. Four short questions can offer distinct reasons to cross existing activities; an optional full directory can retain every current destination and grown-up mapping.

## Smallest behavior

- `#explore` shows one brief welcome, four **unordered** question links, and a closed native `<details>` named **All places**. There is no completion indicator, order, recommended level, adaptation, or prerequisite language. Each question link has a unique URL `#explore/water`, `/sharing`, `/words`, or `/neighbors`.
- A question URL shows its question as the heading, a one-sentence story invitation, three existing direct activity links, and one explicit contrast connecting them. Each link has its own child-readable reason. They are choices, not steps; all three can be opened first. A visible **All four questions** link returns to `#explore`; the ordinary browser Back also works. An unknown or empty slug shows the default four-question doorway with a small “Choose a question” message, never an empty screen or a guessed activity.
- Keep the **same twelve `learningPlaces` entries, titles, marks, bodies, hrefs and scoped topic disclosures** in All places, including the existing closed “Grown-ups: how these places connect” disclosure and `#map` link. No map or topic metadata moves into the child-facing questions. The existing `learningInvitations` and `placeMatches` behavior remains intact.
- The doorway only renders finite literal copy and ordinary anchors. It does not read progress to choose a link, allocate a new save root, update familiarity, call a route’s start action, or claim a visited activity is complete. Clicking a link follows that existing activity’s ordinary route and state policy. Existing global initialization may still run as before. An unfinished saved activity remains governed by its own save policy; **temporary teaching pictures** such as Ribbon Recut and Body Movement restart when revisited and the doorway must not promise to save them.
- Deep links work on refresh and after switching explorers. The four child URLs do not require a previous page or a progress record. No new imported/exported field. Keep shell navigation, header, logo, home and other hubs unchanged.

No route depends on finishing a sibling activity. The water page's third link opens the existing Water Lab hub with mission choices, not an assumed active mission. The food arrow opens its own catalog. Direct navigation to an unavailable old save uses the destination's existing recovery behavior. New merged activities can be considered in a later editorial pass; **do not link unmerged Cold Window, Join Portions, or Budget proposals in this release**.

## Layout and interaction contract

Use the existing Trebuchet/Verdana garden UI, forest/green/mint/cream/yellow tokens, existing rounded paper panels and visible link focus. The mock is an original layout study, not a replacement app shell. The four questions should resemble four separate garden signposts with distinct small marks, alternating quiet paper tones or borders. They are **not numbered** and do not look like ordered lessons. Desktop may use a two-column question grid; 320 px must be one compact column, with the fourth choice reached in ordinary scrolling well before the old twelve-card length. One whole signpost is a native anchor with at least 44 px usable target, title and one-line teaser. No nested links inside it. The question page has a clear back link and three full-width destination anchors, each with an explicit reason; its contrast is a short final note, not a hidden prerequisite.

All places is **closed by default** on every fresh `#explore` render; native summary target at least 44 px. Its open contents are the complete prior twelve-place directory and the prior grown-up map disclosure. At 320/820, no horizontal page overflow. Visible focus follows normal anchor navigation; after client-side hash render, focus the question `<h1 tabindex="-1">` on a question change and the default `<h1>` on return, while preserving sensible browser Back and without stealing focus from an unrelated live route. The current app already focuses its main region on navigation; implementation should verify the resulting focus rather than adding competing focus helpers. Do not inject narration, speech autoplay, animation, or new art dependencies.

The full set of links is semantic navigation; no disabled or locked styles. For keyboard and screen reader use, question links have descriptive text independent of the tiny decorative mark, destination links read their title and reason, details/summary remain native, and focus ring matches the existing `--poppy` rule. In reduced motion the page is static anyway.

## Implementation boundary and checks

Expected small touch points: `dist/learning-invitations.mjs` (finite question data, default/detail render), `dist/app.mjs` (pass the existing slug and active question URL to the renderer if needed), and the existing Explore rules in `dist/workshop.css` or one nearby stylesheet. No new router, package, content registry, storage field, graph edge, atlas count, or global-nav rewrite. Keep the unchanged old directory markup in a small helper to avoid duplicating it on all five route views.

Meaningful checks before review: compare pre/post `learningPlaces` identity and all twelve rendered links/topic disclosures; test all four direct URLs, unknown slug, browser Back, keyboard focus and native summary at 320/820; verify each of the twelve question-page links resolves to its **merged** activity, and there are no progress- or explorer-dependent options. Import an ordinary notes file, navigate questions, switch explorer, and confirm the doorway itself changes no saved root or downloaded notes. Start an existing saved activity, leave through Explore and return, checking its own resume behavior; step the unsaved Movement and Recut pictures and verify the copy does not promise persistence. Visual review should compare the 320 page height to the recorded 4,734 px baseline and inspect the question page plus open All places for readability. No attainment, curriculum coverage, or learning effect follows from a click.

The mock is a design review artifact. Its links are illustrative; the real app supplies header, state and behavior. Independent spec review must clear copy, route truth, compactness, full-directory retention, navigation/accessibility, and the saved-versus-transient distinction before build.
