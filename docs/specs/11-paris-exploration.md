# Paris, a place to return to

Status: implemented; independent spec, content, and implementation review clear.

## Experience

Extend the existing imaginary English-reading Paris visit with three openly available destinations: Lucie’s bookstall, the river walk, and a rooftop garden. Each offers two original story errands, each with two questions and an optional unscored postcard invitation. Each errand has three authored passage variants: a little text, a little more, and a longer passage. This yields six stories, 12 question prompts, and 36 task versions; finite authored content, not unlimited generation. Keep the original six-stop postcard path available and preserve its IDs and saved visits.

The child chooses a destination. Select the least encountered story in that destination, with a deterministic tie break; avoid repeating exact questions until that destination’s two stories have been encountered where possible. Returning to the same story is clearly called rereading. All destinations and three passage lengths remain manually available without gates. No timer, score, badge, punishment, grade or reading-level label. Use the existing illustration plus distinct small original destination drawings/symbols, generous text, touch controls, and optional existing local speech/sentence focus/helpers.

## Adaptation

Choose passage variant independently for each destination, starting with the middle variant. Consider only the latest six completed non-skipped Paris exploration task observations in that destination. A longer variant requires two first-try correct, reported-independent, unsupported answers on distinct previously unseen passages at the current variant. Duplicate answers to the same passage cannot manufacture that evidence. A wrong attempt, retry or explicit help (audio, sentence focus, hint, smaller example, explanation, working together) at the current variant suggests one shorter step on the next errand. Unknown reading alone does not trigger a drop. A skip is neutral. Reading together is welcome; a shorter suggestion is an offer, never a penalty or a restriction. Keep authored comprehension depth available through manual choices.

Use the newest eligible observation’s variant as the base (middle if none). If it shows support/retry/wrong attempts, suggest one shorter variant relative to that observation, not relative to a prior suggestion; do not apply the same event repeatedly to ratchet down. Otherwise suggest longer only with two distinct-story qualifying successes at that base variant after the most recent support/retry signal. Otherwise hold the base. A correct second question on the same passage cannot cancel support on its first question. Skips are absent from the signal window and do not erase prior signals. Familiarity across ALL variants of a story is frozen when its first question is displayed, derived from existing seen nodes. If another length is displayed while an earlier version is paused, mark the waiting draft familiar for adaptation. Only a previously unseen story can supply an advance signal; rereading and manually changing length do not manufacture new-story evidence. With this finite library, fresh signals can run out; do not invent advancement when they do. Manual choices stay available.

Determine a new errand’s route and selection reason once when it starts; do not recalculate its nodes from later performance, reload, or content rendering. Store its concrete node IDs, destination/story/variant and selection reason inside the existing visit. The existing story engine consumes this frozen route (two task IDs plus the existing optional Paris postcard). Validate exact catalog pair/order, postcard tail and matching entrance/destination/story/variant. Reject malformed exploration visits (and their dangling observations) rather than falling back to legacy. Old visits with no exploration marker/route use their original linear links unchanged. Paused visits stay resumable when a different errand is chosen; require the existing explicit choice before switching away from an unfinished visit.

All new nodes remain practiceOnly:true. The second question uses the same passage ID and is rereading; it cannot contribute a second unseen-passage signal. No decoding, fluency, mastery or reading level is inferred. Record selection reason and variant in parent-visible notes/export; retain support and familiarity distinctions. Explain that choices and finite content make suggestions approximate. Observation-driven adaptation uses only local existing state; no AI calls, server learner data, names, mic or new persistence system.

## Content contract

New `paris-library.mjs` exports `parisDestinations`, `parisStories` catalog, `parisLibraryNodes`, and `parisLibraryHelpers`. Destination IDs: `bookstall`, `river`, `rooftops`. Each story: `{id,destination,title,variants:{1:[nodeId,nodeId],2:[nodeId,nodeId],3:[nodeId,nodeId]}}`. Nodes include `parisDestination`, `parisStory`, `parisVariant`, `readingSkill`, `passageId`, and all existing task fields. IDs begin `paris-explore-`. Each pair shares its own stable passage ID and readingText; different variants use different IDs but retell the same errand (exposure selection treats the story itself as familiar, so changing length cannot be mistaken for new reading evidence). All answers follow from the currently visible passage, no Paris trivia or illustration shortcuts. Bookstall targets detail/word parts; river targets context vocabulary/inference; rooftops targets evidence/sequence. Write a small different helper for each target; shared helpers are allowed, and any helper use remains support. Passage lengths roughly 25–40, 45–65, 70–95 words; natural clear prose beats exact counts. Vary answer positions. No copied text or identifying child/family content.
