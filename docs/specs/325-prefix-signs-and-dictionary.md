## 4. Persistence and failure contract

Use optional explorer root `signs`, absent until an explicit bench selection, job selection or mutation. Presentational arrival/story/card reading alone creates no record.
```
signs: {
 v:1,

 view:'prefix'|'dictionary'|'practice',
 prefix:{prefixId:null|id,partId:null|id,kept:[{prefixId,partId}]},

 currentId:null|id,

}
```

Source shapes, all fields required except where noted. The collection jobs list holds at most64 task sources; story has short/longer strings under the ordinary text bound. Collection v1 is structural, not a requirement to contain today’s sections. The root gate requires only an object, v1 and an object source; view/currentId, prefix, dictionary and records are validated where consumed. Missing records read as empty. Missing prefix/dictionary drafts are created only on explicit bench selection using their own readable retained section, never today’s replacement. An unknown view/current pointer shows the chooser. A missing or unreadable saved section pauses that section without substituting current content.

Source shapes:

- `prefixes`: up to16 unique `{id,text,meaning}`; `parts`: up to64 unique `{id,text}`. Initial8/19 are authoring counts, not load gates. `joins`: up to256 `{id,prefixId,partId,meaning}` with unique id and pair; references belong to that saved section. Literal joined label is the two own texts concatenated, not another stored answer. `cards`: up to16 `{id,title,text,example,steps:[string]}` with up to4 manual steps. Empty arrays are readable but unavailable controls explain the missing material.
- `pages`: up to16 `{id,entries:[{id,word,definition}]}`; each page up to64 entries; entry ids unique across this section. Guide words come from that page’s first and last retained entries. Do not validate old entries against today’s spelling or recompute old results. Empty page has an unavailable notice and no invented guide words. Render readable pages even if one sibling entry is malformed; a target whose own entry/page is unavailable pauses only its lookup, preserving it. Initial pages are independently checked for alphabetical order; load validation is structural, not a new sort of retained entries.
- `taskSource`: `{v:1,id,kind:'choice'|'match'|'order',title,prompt,tag?:string,parts:[{id,text}],choices:[{id,text}],key,steps:[string],hint,example,explanation,different:{[id]:string},teach:[card...]}`. Up to16 parts/choices; own ids unique. key is one own choice id, a complete part→choice mapping, or a permutation of own part ids according to kind. Different feedback may retain bounded unused keys. Text up to4000 Unicode code points, ordinary ids1–80 ASCII letters/digits/_/-, arrays/cards limits above; unknown additive fields are retained and ignored unless consumed. Source metadata has no learner age, identity or inferred skill.
- `work`: `{choice:null|ownChoiceId}`, `{placements:{ownPartId:null|ownChoiceId}}` (missing placements read as null), or `{order:[ownPartId...]}` a full permutation. `help` is two booleans. A `check` stores `{work,help,outcome,supported:true,guided:true,feedback:[string]}`; at most12 feedback lines, each≤16000 code points. `snapshot` is `{work,help,check:null|check}` and the check must refer to that exact work, not today’s rule. Count is a safe integer0–1,000,000, at least retained checks length. Retain first plus latest11 checks, maximum12 per task. Keep first/latest snapshots separately. Records cap64. Kept pairs cap256, unique own pairs. No timestamp needed.

Do not require all sections/records from today’s pack, fixed catalog counts or today’s ids. Missing optional roots/records read as absent. Malformed/unknown-version root remains exact, exportable and read-only. A readable root with one unreadable section or record keeps the other benches and jobs open.
