# 314 · One parcel, more than one: labels at Word Garden

Proposed 2026-10-30. A bounded first slice of [254](254-one-seed-many-words.md), not approval of that whole pack. Closes a specific E1-II/E2-I bridge: a noun changes when a connected message names more than one object. Explicit visual construction is supported spelling practice, not decoding, dictation, independent writing or placement. PR254 (the unrelated mill-film PR) remains held.

## Why this slice

Word Garden currently explores meaning-bearing combinations and welcomes invented words. It does not teach conventional plural spellings. Add a small **Parcel labels** workbench at `#words/endings`, linked from Word Garden and back to it. Extend the existing host; no framework, new top-level menu, story unlock, café inventory mutation, real shipment or phonics player. The parcels are a separate pictured practice scene, not real food for an animal. Show: “The café and garden are sharing supplies. Make a label that tells the reader what is in this parcel.” A correct label can be stamped and another request opened; a different label can always be changed. No lives, score, timer or failure gate. Future 254 work must extend this route/controller and preserve its parcelLabels sources and saves, rather than build the proposed Plural Bed again beside it.

## Complete first vocabulary and meaning contrasts

Twelve original noun pairs, checked individually; teach these bounded patterns rather than a universal English algorithm:

| Pattern | One → more than one | Distinction |
| --- | --- | --- |
| Keep the base, add s | bun → buns; cup → cups; pot → pots | Most nouns use s; one keeps the singular base. |
| Keep the base, add es | box → boxes; dish → dishes; brush → brushes | These words end in x or sh; es is the conventional plural ending here. No claim that every ch word, every z word or every noun follows this rule. |
| Remove final y, add ies | berry → berries; cherry → cherries; daisy → daisies | A consonant letter immediately before final y is the clue in these nouns. Taking off y and adding ies gives the same spelling as changing y to i and adding es. |
| Keep y, add s | tray → trays; key → keys; toy → toys | The letter immediately before y is a vowel: a/e/o here. Do not change every final y. |

Adult-readable teaching says these are common patterns, English also has exceptions, and a dictionary or grown-up can help with other words. Offer a simple letter key: a,e,i,o,u are vowel letters; the letters r,s,p used before final y in our examples are consonant letters. Look at the letter immediately before the final y. This is a letter test for these spellings, not pronunciation teaching. Teach plural as more than one. Do not use zero quantities, possessive apostrophes, third-person verbs, irregular plurals, pronunciation claims or an all-English suffix rule in this first slice.

Every source uses count1–5 and the connected sentence “Please send {count} ___ to the café.” or “…to the garden.” Fixed destinations: bun,cup,dish,berry,cherry,tray,key,toy→café; pot,box,brush,daisy→garden. These are fictional practice supplies and never change another game. The singular base appears as “One is called: berry”. The request supplies the count and a picture of exactly that many objects; arithmetic is support, not a hidden pass condition. Art uses twelve distinct original inline SVG silhouettes with readable text equivalents, no emoji-only identity or external images. Pots are flowerpots and daisies are cut flowers. Buns are bread rolls; berry and cherry drawings must be visually distinct with the supplied singular label remaining authoritative. The picture's accessible name is “1 pictured object; it is called {base}” for one, or “{count} pictured objects; one is called {base}” otherwise, never the plural answer. The picture is a work surface with a parcel label, not a decorative hero above a text worksheet. A short visible line distinguishes the modes: “In Word Garden you can invent words. Here we use the usual spellings so a reader can recognize the supplies.”

## Exact game loop and teaching

Default empty entry is a nonmutating preview with **Start a parcel**, using Mixed / Mix quantities and an initially open optional chooser. The learner may change those transient selectors first. Starting explicitly freezes a source. Current work occupies the initial tablet screen; optional instructions and saved parcels are below a native disclosure, initially closed with readable work. Controls are tap/click/keyboard buttons, no drag requirement.

1. **Look and build:** show request, pictured objects, singular base, live label in its sentence and two compact controls. For a y noun, choose **Keep {base}** or **Take off final y: {trimmed}**; for other nouns show the unchanged base only. Select **No ending**, **s**, **es** or **ies**. All four ending choices stay in the same order and none is preselected; the base starts unchanged. The live preview is the literal selected stem+ending, clearly “Your label”, not a corrected spelling. Before an ending selection show a visible blank. “No ending” is a deliberate choice, not missing input. Selecting pieces saves the exact current choices but creates no response record. Show no target plural until requested help or a check. More than one count with a singular draft is a meaning mismatch; an attempted plural with a different spelling is distinguished from that mismatch.
2. **Check this label:** only after an ending is chosen. Compare the assembled label with the source’s frozen expected label. Record the chosen pieces, literal constructed label, match/different outcome, whether help was already shown, and specific explanatory feedback. Every response is explicitly supported construction because the base and tiles are supplied. Preserve the first check and latest checks (up to 24), including first differing results and subsequent corrections; edits never rewrite checks. No automatic next parcel, stamp or mutation elsewhere. A matching check says why the label names one/more than one and explains the spelling. A different check names the actual discrepancy: count1 needs base/no ending; a plural without ending needs a plural form; this selected x/sh word keeps the base and takes es; this consonant+y word uses y to ies; this vowel+y word keeps y and adds s; other selected nouns keep base and add s. Show the exact constructed spelling and target correction, with neutral language. All attempts after a check remain supported/familiar; no retry can become an independent first response.
3. **Keep this parcel:** explicit action after any selected ending, regardless of check or match. Keep exact first and latest snapshots of source, stem/ending, current label, help/check history and optional own-message text. A mismatching kept label is described as a kept draft, never a successful shipment. A matching checked-and-still-current label gets a small static “Label ready” stamp, not a curricular success or town win. Editing pieces removes readiness until checked again; retaining older matching checks does not endorse a new label. First-kept work never changes.
4. **Another parcel:** always open, including after a different check or no check. Current parcel remains in the saved selector. Within a native disclosure choose Mixed, add s, add es, y to ies, or keep y, and count **One**, **More than one**, or **Mix quantities**. Changing selectors is transient/read-only. Explicit creation freezes a new id/source and resets only the new parcel's choices/help/checks/writing. Mixed words cycle the twelve nouns in table order; selected families cycle their three nouns, using nextSerial−1 modulo eligible word count. Counts: One→1; More→[2,3,4,5] indexed by nextSerial−1 modulo4; Mix→[1,3,2,5,4] indexed modulo5. These finite combinations recur intentionally; label the library as12words with familiar returns, not endless unfamiliar reading. No automatic adaptive level, learner rank or cross-strand inference. Manual pattern choice lets the family target a need now; later suggestions require a separately reviewed evidence rule. With One selected, show “This pattern is for more than one. For one, keep the whole word.”

Optional **Show this spelling pattern** reveals the source’s exact pattern and a different worked word: map→maps, fox→foxes, puppy→puppies, day→days respectively; count1 uses “For one {base}, the label is the whole word: {base}.” Help is saved before showing it. This is distinct from the visible base/tiles' always-supported status. Optional “Write a message of your own (a person can read it)” is up to 600 characters, not auto-graded or silently corrected. A short suggestion after keeping invites a grown-up to change the number in a paper café/garden note and read it together; no report of completing it and no decoding/transfer evidence is inferred. No synthesized or recorded phonics audio. Ordinary page narration is out of scope rather than a guessed pronunciation service.


### Exact feedback templates and child wording

Use **y to ies** as the child-facing pattern name. **Take off final y** describes the physical button action, not a different rule. The matching y-family feedback and its help must both include: “For more than one {base}, take off y and add ies: {trimmed} + ies = {plural}. Another way to describe the same spelling is to change y to i and add es.” This connects the visual chunk to later suffix work without naming ies as a universal suffix.

Feedback priority is explicit: first prepend any applicable real-word discovery (to, toes, dais, daises), at every count; then count1 meaning feedback or plural No ending feedback; then the selected family's spelling explanation. The discovery never replaces the correction for this pictured request. Prefix every check with the literal sentence “Your label: {constructed}.” Matching feedback begins “That label fits this request.” Different feedback begins “Let's adjust this label.” Neither claims a failed learner or invalid invented word.

- Count1 match: “{base} names one, so the whole word is the label. No ending is needed.” Count1 different: “For one {base}, keep the whole word: {base}. Choose No ending.” For y-noun corrections also name the actual stem action: “Choose Keep {base} and No ending.” This correction applies even if the child trimmed y or added a plural ending.
- Plural with No ending and unchanged base: “There is more than one. In this request, {base} names one. The usual label for these supplies is {plural}.” Follow with the family's exact explanation below.
- Plural with No ending and trimmed stem: “The usual label for these supplies is {plural}.” Follow with the family's explanation. Do not call a trimmed construction a fragment or a singular noun; dais and to are real words.
- Real-word discoveries: toy→to + es: “Toes is a real word for parts of a foot. This request is about toys.” toy→to + No ending: “To is a real word, but it does not name a pictured supply here.” daisy→dais + No ending: “Dais is a real word for a raised platform. This request is about flowers.” daisy→dais + es: “Daises names more than one raised platform. This request is about flowers.” Then append the count/family correction for the source. Treat these as meaningful discoveries with different referents, never misspelled nonwords. The live preview remains literal, even when its sentence reads awkwardly (for example, “Please send 3 to to the café.”); checking explains why it does not name these supplies.
- add s explanation: “For more than one {base}, keep {base} and add s: {base} + s = {plural}.”
- add es explanation: “{base} ends in {x or sh}. For more than one, keep {base} and add es: {base} + es = {plural}.”
- y to ies: use the full equivalence wording above. Follow: “The letter before y is {r,s,or p}, a consonant letter.”
- keep y: “The letter before y is {a,e,or o}, a vowel letter. Keep y and add s: {base} + s = {plural}.”

The four plural worked examples are map→maps, fox→foxes, puppy→puppies and day→days. Help uses the same explanation for its worked word, then applies the pattern to the current target; supported exposure is explicit. All label strings and template choices must be frozen in the new source/check rather than reconstructed from tomorrow's content. Final implementation content reading must inspect instantiated feedback and artwork, not only these templates.
