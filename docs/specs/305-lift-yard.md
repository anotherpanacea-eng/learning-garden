## Exact bounded model

`lift-yard.mjs` owns original pure model/selectors, scene and UI with no external runtime. `lift-yard.css` owns the component. Height goal `h=1m`, load weight `w∈{12,24}N`, slope-board length `L∈{2,3,4,6}m`, winch maximum rope pull `c∈{2,3,4,6,8,12}N`, largest supplied board `b∈{2,3,4,6}m`. A job supplies every listed board at most `b`; boards are reusable model choices, not an inventory consumed by a trip.

Catalogue: enumerate triples in `w` ascending, then `c` ascending, then `b` ascending, retain those with at least one `L≤b` and `w/L≤c`. Exactly28 distinct triples. Prefix these six in order, then the remaining enumeration without duplicates:

Selectors/transition reject out-of-range requested indices/enums; no generic validator, registry or saved-source regrading system is commissioned.

Required steady rope pull `F=w*h/L=w/L` N, independent of the winch's maximum. Supplied stock permits `L≤b`; capacity permits `F≤c`. The winch adjusts to required `F`, not always its maximum `c`. Previewed force is a calculated requirement, not a live measured force or net force. All selected values give integer `F∈{2,3,4,6,8,12}`. Planning keys stay visible in physical ascending length order; they are parameter controls, not shuffled answer cards. Fitting lengths vary among cases and multiple fits are valid.

For an active trip, distance `d` along the ramp advances by exactly1m to a clamped `L` per explicit **Pull rope1m**. Height gained is `d/L` m; rope work so far `E=F*d` J. Calculate full rope work as `F*L` and separately verify `F*L=w*h`; the result is12 or24J. This is positive rope work/gravitational potential energy gain in the load–Earth system, not the net work of all forces on the drum, which is zero in ideal steady motion. Weight is a force in newtons, not mass in kg. Rope pull is parallel to the ramp; the ramp's support and gravity also act. Starts/stops, changes in speed, friction, rolling, winch losses and human metabolic effort are not simulated. A holding brake keeps the drum at a checkpoint; a stationary brake does no mechanical work. No real equipment or prediction for a real lifting apparatus.

## Actions and preservation

- **Board key:** changes draft and clears notice only. An active trip is not erased. Plan preview uses draft; when it differs from active ramp, preview is at bottom; only if started does text say the current trip waits. Same active ramp previews its actual distance.
- **Start this ramp / Continue this trip:** if stock fails, stay in plan with stock explanation; else if capacity fails, stay with force explanation. Preserve any earlier active trip. If a valid draft equals an already started ramp, resume that trip/distance. Otherwise start a new setup at distance0; same job and its earlier delivered flag remain. No gate on typed answers.
- **Change plan:** show plan with draft equal to active ramp, retaining distance and delivered flag. Only when started and a different draft is previewed, **Keep current trip** restores the active setup/turn without losing its distance. Only when started, the new-setup action says it starts from the bottom and, only for a valid startable draft, warns that it ends the waiting trip. Invalid drafts show only equipment refusal and preservation. Unstarted stock refusal and preview never claim a waiting trip.
- **Pull:** only on a started valid active trip at distance<L. Increment/clamp; at L set this job's delivered flag true. Repeating the last pull is a no-op/refusal. Focus moves from the disabled pull to the rendered next action. **Return drum to start** immediately resets distance0 without animation on the same started setup, without undoing that job's earlier delivery.
- **Other deliveries / Return to current job / choose slot:** page changes and current slot selection keep every work object's plan, active distance, notices and turn. Switching away from a partly completed job never starts it over. No requirement to finish one before viewing others.
- **Next delivery:** available after reaching the top. Select the next undelivered slot cyclically, preserving its work; when all delivered, open jobs page. All delivered flags count once, even if a job is replayed with another plan.
- **Keep this trip / Replace held trip:** only at current top mark; copy weight and ramp length, not a reference into mutable state. Clear explicit. An earlier completed trip's physics is not proof its board/capacity fits today's job. Another shift retains the held physics comparison and chosen representation, resets only six work objects/current/page to first plan.
- **Yard / Numbers:** change representation only. The same plan/pull actions remain available, with the same job, progress and equipment. Optional local **Hear this turn** reads supplied visible information; it does not record perception or reading competence.

Held comparison uses the visible plan: draft while planning, active ramp while pulling. Mark a draft as planned, including stock/capacity failures. It uses full planned length/work alongside an earlier completed trip, with travelled distance/work-so-far separately labelled. Same weight/height with a different L permits a force–distance contrast. Same L/different weight permits a load contrast. When both weight and L changed, say both changed and give quantities; never attribute a force change to only length (e.g.12N/3m and24N/6m both need4N). Keeping a trip does not award assessment or increase completed-job count.
