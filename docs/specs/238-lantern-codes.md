## Story and learning

Dot has repaired the Post Office tower lantern after the storm. Pip flashes toward the bakery, but the baker cannot tell whether he means hello or bread. Help Dot agree on four pretend messages: **All safe**, **Water rising**, **Boards in**, **Come help**. All pages remain open; this is not a real warning device or a replacement for the story's courier/runner. No act completion, reward currency, score, timer or global science/math level.

Teach, demonstrate, design, send and compare: a signal is the observable pattern; a message is its agreed meaning; different codes can carry the same message; a quick code can fail under a changed observation rule. A later firsthand-source comparison can ask what Dot actually observed, but no automatic cross-subject proficiency or shared mastery inference is added.

The core is construction and testing, not multiple-choice recall. No Set1 graded question pack is commissioned. All saved tests are computer-model results, not evidence that the child calculated, decoded independently or understood the concept. ## Exact model

Current source `lamp-code-v1`: four stable message ids `safe`, `water`, `boards`, `help`; patterns are1–5 S/L flashes, clear observation is the whole sequence; rain removes every S and closes all gaps, retaining only the ordered Ls. Empty observed strings never carry a decoded message. The receiver has no clock, position or hidden sender-duration cue in rain. Sender cost still counts all original flashes/gaps; label it as sender cost, not receiver evidence. This deletion model is fictional: "Real rain does not hide every short flash. Here, pretend rain hides short flashes; Dot sees only the long flashes, with no clues from the missing places."

Each Send is one externally framed message; Dot knows where this message starts and ends. Code A is not prefix-free and is not a continuous-stream protocol. Sender beat totals exclude boundary/framing cost. No Morse timing or real-radio reliability claim follows.

Sending an unassigned/empty selected pattern refuses without adding a test or changing state, with “Give this message at least one flash.” Test all four instead records an `unassigned` row for each blank sender message (observed empty, no candidates, no decoding), even if Dot lacks a card. A complete sender pattern erased by rain is `invisible`, a distinct outcome. Incomplete designs show only a labeled partial beat total and cannot count as a complete successful code.

For nonempty transmission, compute its observation. If empty: invisible. Otherwise if no receiver card: no-card. Otherwise compare to observations of assigned/nonempty receiver patterns under the same weather: zero candidates=unlisted; multiple=ambiguous; unique matching intended id=read; unique other id=read-other. Blank receiver entries are not candidates. All-four success requires every sender message assigned and all four actual results read. Design robustness with an imagined matching card requires all four assigned observations nonempty and unique. Duplicate original patterns fail clear and rainy robustness. Model constants/labels/copy freeze with each visit; helpers use saved rules, not today's catalog.
