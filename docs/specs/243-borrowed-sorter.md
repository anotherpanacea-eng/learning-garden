## Purpose and source boundaries

The post office borrows a brass-and-wood sorter from Les Saules. It sends every Hill parcel to Town. Help the postmaster inspect how it decides, compare overall and destination-specific results, change features/examples, and write advice. The goat is an unexpected visitor, never a joke about the farmers' intelligence. All five pages are open without story, age, grade or attainment gates. The case is available independently of Act I completion.

This is a finite **exact-match lookup model with a majority vote**. People chose its procedure, visible features, example labels, tie rule and fallback. It is an analogy for examining example-based classification, not a claim that all AI works this way or that machines have no human-written rules. No model API or runtime training. All examples are fictional postal destinations, not demographic groups; these accuracy comparisons cannot establish comprehensive fairness. Correctly labelled examples can still be unrepresentative or fail to distinguish destinations.

## Exact simulation and available changes

Features: size (small/large), wrap (brown/blue), road (valley/hill). Destinations: town/hill. A weighted row owns id, the three feature values and nonnegative integer town/hill counts. Baseline rows, in that order:

| Size | Wrap | Road | Town | Hill |
| --- | --- | --- | ---: | ---: |
| small | brown | valley | 12 | 0 |
| small | blue | valley | 10 | 0 |
| large | brown | valley | 8 | 0 |
| large | blue | valley | 6 | 0 |
| small | brown | hill | 0 | 4 |

The supplied test batch is respectively 9/0, 8/0, 7/0, 6/0, 0/4 for those rows, plus large/brown/hill 0/6. Baseline totals36/4, test totals30/10. The augmented corpus adds only small/brown/hill0/4 and large/brown/hill0/6 once. Switching back restores baseline; selecting an unchanged profile does nothing. No arbitrary parcels, features, labels or repeated additions in the current source.

For each test row find every training row matching all selected features. Empty feature set matches every training row. Sum destination counts in matching rows. If no matching rows (or matching rows carry zero weight), use the whole selected corpus. Larger count wins; equal counts, including an empty corpus, give `none` and “No majority in this model.” Never silently route a tie. A trace owns matched row ids, match counts, fallback-used, actual vote counts and destination. Record each test row's intended counts, routed destination and correct counts. Ties count as not correctly routed for both destinations; show them separately as undecided. Denominators count actual labelled parcels. With zero denominator show “No parcels in this group,” percentage null, not0% or100%. Whole-corpus fallback must be distinguishable from an exact match. No destination is inferred merely from the road; road works here because of the supplied labelled examples.

The eight feature subsets × two datasets give exactly16 profiles. Independent oracle expected overall/Hill correct counts, out of40/10:

| Features | Baseline | Augmented |
| --- | --- | --- |
| none | 30/0 | 30/0 |
| size | 30/0 | 30/0 |
| wrap | 30/0 | 30/0 |
| road | 40/10 | 40/10 |
| size,wrap | 30/0 | 30/0 |
| size,road | 34/4 | 40/10 |
| wrap,road | 40/10 | 40/10 |
| size,wrap,road | 34/4 | 40/10 |

Using the test batch to select features already makes this a design exercise. Adding ten Hill examples from that same test batch contaminates any claim of unseen evaluation. Every run/comparison names the finite supplied batch and, for augmented examples, explicitly says some of these parcels were used to change the model. 40/40 here never promises future success. “More features/data always helps” is explicitly contrasted with these results. There is no endless bank or adaptive level claim.
