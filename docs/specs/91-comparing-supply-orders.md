## One new learner action

The fixed pair is **23 and 11 pretend seed counters**. The learner can first *match* Pip's and Dot's separate collections to construct an excess, then use the same two numbers in a *return* story to construct what remains. Both number questions have the answer 12, but the 12 counts different things. Matching never removes a counter from either crate; returning actually moves counters to a store tray. The child chooses what their number counts separately from entering the number. This is a meaning contrast, not another regrouping exercise or a general subtraction algorithm.

The existing Exchange Table keeps one quantity unchanged while regrouping, Joining Orders combines distinct origins, Returning Orders models 42 minus 12 or 17 with an optional opened ten, and Equal Groups changes a group unknown. The broad Number Garden has a 17 minus 8 take-away story. None presents **the same two quantities** in adjacent comparison and take-away pictures with a learner-built match and an explicit meaning choice. This task needs no opened ten: 23 is two wrapped tens and three ones; 11 is one wrapped ten and one one. One ten-pair and one one-pair leave one Pip ten and two Pip ones unmatched. Returning one Pip ten and one Pip one likewise leaves one ten and two ones on Pip's table. This deliberately holds calculation simple so the changed referent is visible.

Use the existing Bundle Burrow home and an open `#numbers/compare` route. Link from the Number Garden and the two supply-order activities as an invitation, never a prerequisite. The optional `comparisonSupplies` save root is separate from `returningOrders`, `joiningOrders` and `bundleExchange`; no old root, stock, answer, café order or broad baseline is edited. ## Exact actions and checks

The comparison model is `{pairedTens:0|1,pairedOnes:0|1}`, initially zero. **Match ten** increments the former once; **Match loose** increments the latter once. Undo decrements the corresponding positive value. `paired = 10×pairedTens + pairedOnes`, `extra = 23−paired`, and `dotLeft = 11−paired`. Full comparison is exactly `{1,1}`. Match/undo never changes the two source amounts; the unpaired Pip amount at completion is 12. The return model is `{storeTens:0|1,storeOnes:0|1}`, initially zero. Return/bring-back change only the corresponding value; `store = 10×storeTens + storeOnes`, `table = 23−store`, `tableTens = 2−storeTens`, and `tableOnes = 3−storeOnes`. Full return is exactly `{1,1}`. The store never exceeds the one-ten/one-one target.
