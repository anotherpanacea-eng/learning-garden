# 313 · The active Linear page comes first

Proposed2026-10-30. Presentation/navigation repair at the existing `#learn/math` scene. Original sources, evaluator, generation/suggestion logic, exposure preflight, saved schema and all open destinations remain unchanged. PR254 stays held.

## Concrete problem

The new signed/zero browser screenshots show a large creation panel and the full fixed/saved lesson catalog above the current page. With nine or more saved visits, the model and task are far below the first screen. The layout should present the active work first and keep changing/opening visits available as a quieter deliberate choice. A new lesson, mastery state or global navigation framework is not needed.

## Native disclosure and preservation

Use the browser’s details/summary and existing controller. No saved field or general visit-state registry. Deliberate disclosure open/close must preserve the actual task/input DOM, pending DOM-only refused text, work/source/answers/history and selected model input. It must write nothing. Choosing a challenge in the chooser remains a transient select until the existing explicit create action.

Preserve the disclosure’s open state across the current controller’s own same-visit redraws (page change, input stepper, help/check/skip, keep). Capture its state before redraw and restore only when the notebook/owner/route and selected active source still match the original binding. Preserve an explicitly changed challenge selection and a still-valid selected removal target across these same-visit redraws. Untouched challenge defaults may follow an updated suggestion. Reset the local explicit-choice marker on the same replacement/new-visit boundaries; a removed target resets to empty. New lesson/create, notebook/import/explorer replacement, route departure and full reload reset to the appropriate default. Selecting the already-current lesson can preserve its disclosure. Every confirmed removal explicitly keeps the chooser open and focuses its visible Another investigation heading, even if removing the active source leaves a different requested preview in place. Cancelled removal leaves its existing DOM/state/focus intact. A fresh no-work state otherwise defaults open. No automatic source selection or successful learning record follows from opening the chooser.

Existing actions must reject a disconnected root/control, wrong route/owner or controls hidden inside closed details. This applies to programmatic retained clicks as well as native actions, including the chooser’s anchors (Download notes and the moved Courier link), not just button handlers. Do not treat closing details as permission to lose edits. Existing unsaved/refused-input guards continue blocking destructive task changes, page changes and departures; the two nonmutating model/page jumps and disclosure toggle may still work without discarding the typed value or creating a save. Closing a disclosure uses native summary focus; same-visit redraw must not leave focus on hidden controls. Start/create should retain the existing focus on the new active page; confirmed/cancelled removal keeps its existing selected-only/confirmation behavior.

Pure `linearPage` and `linearNotes` readers stay pure, including unsupported/additive roots. Closed chooser contents remain in the DOM for accessible disclosure semantics, but are not keyboard targets until open. All fixed/generated visits remain reachable after expansion; hiding a catalog is not a prerequisite or learning gate.

## Layout and scope

Use the existing palette, type family and restrained surfaces. Reduce header scale/spacing within the Linear scene only; no global header/menu or new audience theme. The task and graph should be the dominant content. At820×1000 and1024×768 in a synthetic notebook with at least12saved visits, active page and reference headings must be visible on initial active entry without scrolling. At320×600, page controls and jump buttons bring the relevant heading into view with no horizontal overflow; do not claim everything fits on one phone screen. Native touch/keyboard, reduced motion and a browser rendering check at150%root font size are required. This is a text-size stand-in, not browser text zoom. Physical iPad keyboard/Safari/VoiceOver remain unqualified.

This is a UI repair, not a new learning capability. Existing Jane/Marble-derived boundaries, original teaching and licenses from312/223 are unchanged; no upstream code/content/graph or learner evidence rule is adopted.
