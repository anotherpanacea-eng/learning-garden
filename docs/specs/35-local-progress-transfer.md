## Behavior

In Grown-up notes, put a prominent “Bring progress from another site” panel beside the existing download action. Explain: open the old address in the same browser/device where progress was saved, select the right explorer, download notes, then choose that JSON file here. Multiple explorers move one file at a time. File selection only reads locally; no upload, account, cloud sync, or remote recovery. Keep the old address/files until satisfied. Save-off imports are session-only and say so.

Choosing a file (maximum 5 MiB) validates it without writing storage or changing explorers. Accept the version-1 raw state and historical/current notes reports containing that state at the top level. Reject unreadable JSON, unsupported root versions, invalid original task records, non-object module roots, unsafe object keys (`__proto__`, `constructor`, `prototype`, `toString`, `valueOf`), extreme nesting (>60), node count (>200000), non-finite numbers and invalid baseline counts. No HTML is rendered from filenames or file metadata. Report root validity is checked using `restoreStateResult`; use the app's existing destination restore rules on a detached clone, catching failures before any commit. Probe the shared destination-notes renderer on a detached copy and type-check original task text fields, so a notebook cannot commit and then immediately crash the selected notes screen. Preserve the exact original file as a kept copy; existing normalizers may close unavailable questions or repair invalid optional fields. Unknown extra fields remain in the state; raw recovery is always downloadable. This is compatibility checking, not authentication or proof of learning.

Preview only recognized picture/color/symbol, total original task count and names of recognized destinations present. Do not display arbitrary metadata/text. Explicit “Add as a separate explorer” confirmation and “Cancel” precede import. Repeated files add separate explorers rather than merging/deduplicating histories. If picture/color/symbol are occupied, choose an unused combination and explain that a distinct explorer marker is assigned. The importer adds no inference or promotion of evidence/support flags. Normal conservative destination restore rules still apply (for example, a saved help flag may close an independent claim); compare imported state to a normal restore, not to unsanitized input. Keep the selected profile avatar and state.garden.avatar consistent even if the marker fallback changes the avatar; exact source stays recoverable.

## Storage and integration

Extend ExplorerStore with an additive import operation. Allocate an unused explorer id and marker without mutating the current registry; do not replace any existing explorer or state. Read the current saved registry and refuse a stale in-memory explorer list; check it again just before commit. Do not roll back over a different intervening registry. This detects observed cross-tab changes, not an atomic cross-tab lock; instructions ask for one destination tab during import. Saving on: save the new state and exact original recovery copy before committing the new registry (registry last). Before the registry write, failures leave current sessions/registry unchanged. A registry write may succeed before read-back verification fails: attempt a verified rollback to the exact prior registry. Clean up newly allocated keys only if the prior registry is confirmed intact; otherwise preserve all imported keys, block further persistent writes for this session and report an uncertain save with reload guidance, never a success claim. Never delete existing state. Orphan keys after failed cleanup remain recoverable; ordinary retries allocate a new id. Saving off: keep the imported explorer and raw recovery in memory, no persistent writes; normal save-on persists both, save-off/reset honor existing data controls. Storage unavailable/write-blocked: refuse persistent import rather than silently claiming success. Once successful, select the imported explorer via existing initialization/navigation and show a success notice on notes. The source tab and file remain unchanged.

Separate progress-transfer module owns bounded file parsing, detached app initialization and preview. Reuse the same initialization helper for normal startup/useExplorer/import so restore rules agree. ExplorerStore owns state allocation/commit; UI owns file input, preview/confirm/cancel/error, no state copies in URLs. Use a standard accessible file input with 44px actions, keyboard focus/status, no drag/drop dependency. Selection is canceled on explorer switch or leaving notes; a stale asynchronous file read may not import into a changed screen/session.

This is storage portability, not a new learning capability. It reuses existing report/state/explorer conventions and previously reviewed Jane/Marble-informed evidence distinctions; no upstream curriculum/runtime/schema or coverage changes are appropriate.
