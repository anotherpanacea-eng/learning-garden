## Story and finite cases

Wren is routing recovery parcels to three pictured baskets: **Cart**, **Lantern**, **Leaf**. Each parcel has a small/large size, a blue/yellow wrap and a star/circle/square stamp. A case freezes all twelve possible combinations, each with a safe unique ID, title and feature codes. Card art repeats size in actual relative dimensions and a clear size label; stamp is a shape, wrap has both color and stripe/dot pattern. Neither size nor wrap relies on color alone. A native parcel selector chooses one at a time beside its picture; do not stack twelve large cards vertically.

All three cases are open immediately, with separate waiting programs/traces:

| ID | Frozen request | Intended rule | Decisive contrast |
| --- | --- | --- | --- |
| large-first | Large parcels go in Cart. Of the rest, star stamps go in Lantern. Everything else goes in Leaf. | if large → Cart; else if star → Lantern; otherwise Leaf | Large blue star goes to Cart, even though it has a star. |
| star-first | Star stamps go in Lantern. Of the rest, large parcels go in Cart. Everything else goes in Leaf. | if star → Lantern; else if large → Cart; otherwise Leaf | The same large blue star now goes to Lantern. Small stars, large circles and small squares do not distinguish these requests. |
| not-blue | Anything that is not blue goes in Leaf. Blue parcels go in Lantern. | if NOT blue → Leaf; otherwise Lantern | Also accept if blue → Lantern; otherwise Leaf. Merely turning NOT on without swapping destinations is different. Cart is unused. |

The third case admits a single-test rule by explicitly switching off the second row. Correctness for a new comparison is **agreement on all twelve frozen parcel combinations**, not equality to one authored program string. Extra unreachable tests, duplicate basket destinations and the equivalent positive/negative formulations are allowed if they route all twelve as requested. A single fitting parcel is never described as proving the full rule. The old desk's star/circle-only source is not relabeled with square or size.

## Build, step, compare

Three short pages: **Build rule**, **Step one parcel**, **Compare routes**. Request, selected parcel picture and compact current-rule sentence remain near the current job; earlier history stays in explicit folds or selectors. Navigation preserves the editor, prediction and partial trace. No scrolling through another game's inventory, no drag-only ordering and no keyboard-only behavior.

The bounded editor has:

- First row: test, optional NOT checkbox, basket.
- Second row: test, optional NOT checkbox, basket; the test selector also offers **No second test**.
- Otherwise: basket.
- **Swap the two rules** swaps both complete test/NOT/basket tuples. It is available only when both test rows have actual chosen tests, not unset/off rows; it resets the live trace/prediction but preserves earlier records.

The seven positive predicates are size-small, size-large, stamp-star, stamp-circle, stamp-square, wrap-blue, wrap-yellow. NOT reverses only that predicate's Yes/No, never the full program or basket. Test/basket selectors begin unset; NOT begins false. Second test null means unset, while `off` is an explicit single-test choice. When off, its stored basket/NOT settings may wait but are ignored and visibly inactive. A program is runnable only with first test+basket, otherwise basket, and either second test+basket or explicit off. Every individual edit is reversible by selecting again, resets only the live trace and prediction, and leaves history intact. There is no code-entry field or arbitrary expression parser.

**Find a parcel both tests catch** searches the frozen twelve for one satisfying both chosen (possibly negated) tests. It selects that parcel, resets the trace/prediction and records supplied contrast support. If the tests cannot overlap in this source, say so and keep the current parcel/program. This action does not answer a quiz or record correctness. **Try the other priority** is represented by the explicit Swap action, not an automatic correction. The three cases' different requests remain plainly separate from the machine's behavior.

On Step one parcel an optional basket prediction (three source basket IDs, unsure or null) can change only before the first test; it is unscored and separate from the requested destination. A single primary button advances one meaningful step:

1. **Read the first test** records its feature/value/negation/observed value and Yes/No.
2. If first Yes, **Use the first matching rule** chooses its basket and explicitly marks the second row **Not tested: the first rule matched**. Do not evaluate the second predicate for this trace or call it false. If first No and second is active, **Read the second test** records its Yes/No. If second is off, **Use Otherwise** chooses the default and marks it off, not false.
3. After a second test, **Choose the matching basket** selects its basket for Yes or Otherwise for No. State that exactly one basket is chosen.
4. **Send this parcel** appends an immutable run, then shows the selected destination beside Wren's requested destination. Different destinations invite revising the rule, never blaming the parcel or grading the prediction.

A first match takes three presses (read, choose, send); a tested second row takes four. No run is appended before Send. **Start this trace again**, another parcel or an editor edit restarts live steps/prediction only. A result must use the exact run ID created by that Send, never scan backwards for an older matching result when a current record is malformed. After changing the editor, an older result can remain selected on History, clearly marked recorded, but cannot masquerade as the current trace.

Compare routes offers **Check all twelve kinds** without a gate. It copies the complete current case source and program once, records one row per frozen parcel (actual basket, requested basket, match), and displays a compact table with pictures/text and a match count. Both matching and differing rows remain visible, with the large-star overlap easy to find. Running a new comparison explicitly replaces only the latest comparison; disclose this before the button. If the editor changed since that comparison, mark it earlier and keep its source/program/results as recorded. No continuous auto-run or hidden grading. Shape-check recorded comparison rows/counts/booleans without recomputing their historic results against today's catalog or today's request. Do not claim arbitrary unseen parcels behave the same beyond the declared twelve-feature space. Equivalent NOT/positive programs can each be compared and their agreement is stated only for this space.
