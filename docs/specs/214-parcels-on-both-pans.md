## Purpose and finite content

The market needs to compare matching sealed parcels. P names one whole parcel’s model mass, identical for every parcel within a case. A different case may have a different P. Same mass removed from both sides keeps an equality; removing a parcel is valid because those parcels have equal mass even before we know it. One-sided changes are reversible experiments, not reasons to leave the game. Link the pictured operation to a true relation on each ledger line, and use equal groups to get from `2P = 8` to `P = 4` without splitting a parcel.

## Actions and physical meaning

Each side has loose whole parcels (0–5), unit weights (0–20) and closed bags (0–3). A bag contains exactly one of the same parcels plus its source’s bag-unit amount (0–4, authored2). A representable side has `loose parcels + bags ≤ 5` and `loose units + bags × bagUnits ≤ 20`, so every bag can be opened within the same picture capacity. P is1–12; maximum pan mass80. No add/subtract by guessed value: the fixed source mass drives tilt and relation.

Controls near the picture:

- **Take one parcel off each pan** and **Take one unit off each pan**. Both sides must have the loose object; neither changes on refusal. Closed bag contents cannot be removed until opened.
- **Open a bag on the left/right** converts one bag into one loose parcel and the stated unit weights on that side; preserves its total. No automatic bag opening or expansion.
- A clearly labeled optional **Try changing one pan** fold offers removal of one available parcel or unit from one chosen side. It can break equality; explain the actual new relation and let Undo repair it. It creates no penalty or incorrect-answer record.
- **Share each pan into [2–5] equal groups** acts only with no closed bags and every parcel/unit count on both sides divisible by that group count. Each group contains whole parcels and weights. Compare one group from each pan; the other identical groups are explicitly set aside, not vanished or split parcels. A compact before/group sketch and label explains the action. Dividing both sides by a positive number preserves equality or the direction of a difference; it does not fix an earlier unequal balance. Refusal names unavailable whole groups and changes nothing.
- **Undo last move** restores the preceding pictured counts and removes that move’s live ledger row. **Return to start** explicitly clears the live move path and current proposal but preserves help, earlier checks and first kept work. No hidden reset or new guest/order.

No unrestricted adding in this first new mode. Each forward move removes objects, opens a bag, or reduces nonzero whole counts by sharing; the live path therefore stays finite (at most56 forward steps under the stated capacities; keep at most64 live move rows). Undo pops the row; trying again does not append an audit trail of undone actions. A no-op share where all counts are zero is refused. This bound is a model limit, not a timed game budget. Later additive transformations need a separately reviewed mode.

A ledger row retains the pictured before/after counts, operation code/parameters and displayed relation at that time. Its expression includes actual loose coefficient P, units and unopened bags, e.g. `3(P+2)`; zeros can be omitted without changing meaning. Use `=`, `<` or `>` according to the source model, with plain words beside them. After a one-sided experiment do not keep printing a false equality. Every line is its own relation; never `2P = 8 = 4`.

**Inspect earlier line** is a view-only ledger selection: show that row’s kept picture/words and mark it “Earlier line”; the current arrangement, proposal and controls remain waiting. **Back to current** restores the current picture. Do not apply new moves to a viewed earlier line. Disable move controls with an explanation while an earlier row is inspected, or place those controls only on the current view. Checking a proposal always uses the current arrangement and source, never the selected old picture.
