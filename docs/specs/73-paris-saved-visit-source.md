# Paris: keep the page that was actually read

Status: independently reviewed specification, 2026-10-22. Claude reviewed the initial candidate and focused fold; the final visit-filter clarification below resolves its remaining P2 as requested. Implementation and its independent review remain pending. This is the saved-visit prerequisite for [Library read-alouds](proposed/library-read-alouds.md), not a new lesson or a new coverage claim.

## Problem and scope

A Paris visit stores answer positions while its renderer and scorer read today's catalogue. Editing a sentence, choice order, answer key, hint or helper can silently change a paused response. Freezing only the current question is insufficient: a second question rereads the first question's passage after an update.

Repair English Paris exploration (including reviewed packs) and the original English Paris route. French has the analogous issue in shared code; preserve its current behavior in this bounded increment and record a separate follow-up. Other destinations and their saves remain unchanged. Do not add an authoring service, source registry, hashes, network storage or account system.

## Required behavior

1. **Capture one visit's supplied pages at start.** Deep-copy the selected English Paris route's node content and smaller examples into that visit, once. Include both exploration questions and their optional postcard, or the original route's six questions and postcard. Keep the existing selected story, destination, length, route, selection reason and IDs. A compact versioned field on the visit is sufficient; no root schema migration is required.
2. **Keep the whole reading context.** The copy includes displayed title/body/guide, passage sentences, passage ID and reading focus, prompt, task kind, choices, fitting index, ordering items and display permutation, hint, explanation, talk prompt, postcard options, and the helper's text, choices, key and text model. A small visit title and any displayed learning-connection wording also belong to the captured source. Preserve the compiler's permutation; never reshuffle on resume. For the original route, node order lives inside the captured source, not a new top-level `route` property (which currently denotes an exploration visit). Both resume-progress traversal and completion read that captured order. Capture the reading-focus label and Paris ending text as part of the visit too; changing catalogue wording must not relabel those pages. Next-node links follow this visit's captured route. No scoring against today's text/key, regrading recorded results or automatic source refresh.
3. **Use the captured source everywhere.** Display, local narration requests, sentence focus, hints, helpers, ordering controls, submissions, completion and new observations use the same saved source. Completing the first question cannot switch the second to a newer passage. Newly created visits use current content. Existing support/familiarity/reading-mode distinctions and open destinations remain unchanged; no reading-level or decoding claim is added.
4. **Validate against itself.** Check the finite source version, types, supported task/model shapes, safe string/array bounds, unique route IDs, node/route linkage, in-range answer and choice positions, complete order permutation, and matching helper identity using the saved content. Do not compare text, choices, keys, counts or helper IDs to the current catalogue. A later missing/changed catalogue entry must not erase a captured visit. Keep historical outcome flags as recorded. Do not add mathematical consistency checks unrelated to rendering or actions.
5. **Legacy saves are records, not reconstructable pages.** A pre-change English visit lacks its original source. Preserve its raw drafts, selected indices/order, attempts, support, IDs, progress and completed observations. Never populate that source from today's catalogue. An unfinished legacy visit opens a calm recovery page: its earlier work is kept, the exact old page was not saved, and a new visit can start. Show selected positions and ordering positions in Grown-up notes without guessing original text or a missing choice count (say “choice position 2,” not “2 of 3”). A completed observation already containing its own prompt/choices can keep displaying those; an old helper without its own source uses positions, not today's helper text. Preserve completed visits as historical endings without assigning new completion. A legacy visit is not a failure and does not create a new assessment observation.
6. **Recovery is local to that visit.** Unknown/malformed frozen sources remain retained and noninteractive, with the same fresh-visit and navigation options. Do not silently downgrade them to legacy or repair them from current content. A fresh-start action creates a separate current-content visit, retaining the original. If that story is no longer available, offer its map rather than silently substitute a story. Other Paris visits, French and other destinations stay usable. Preserve raw records through export/import, explorer switching and save-off behavior; reset remains the existing explicit explorer reset. No new data sent anywhere. Cross-visit writes to `familiar`, `priorPassageSeen` and `knownFact` must skip retained legacy/malformed raw drafts. Lookups for captured visits use their own source, including when the catalogue node no longer exists. Their exposure history may inform a new visit, but never rewrite the retained record. Fresh-start recovery calls `startVisit` directly rather than the path helper that resumes an existing visit.

For retained legacy/recovery visits, only bounded shape checks apply: retain their stored `node`, `finished`, raw drafts, recorded IDs and observations without recalculating progress or source content. The load path must explicitly bypass the current-catalogue visit-level `validateParisRoute` deletion filter, `allowed`/`ownNode` filtering of recorded IDs and drafts, traversal/progress recalculation from current `storyNodes`, and current-catalogue `cleanHelper`, `cleanReadingRecord`, missing-node observation filtering and metadata checks for retained English legacy/recovery records. For captured visits, these operations use only their own validated source. In particular, do not delete an old helper because today's helper ID changed, trim its choices/steps to today's helper, clamp sentence focus to today's passage, overwrite saved reading-skill/passage labels, or borrow current helper labels in notes. Order-attempt permutation indices are described as stored card positions, with no guessed text.

**Storage budget.** Each newly captured source must fit within 24 KiB of UTF-8 JSON; reject a new start with a clear notice rather than truncate its content or mutate a waiting visit if an authored route exceeds that budget. This is a cap on newly authored copies, not a reason to delete an older record. As a representative repeated-use probe, 200 captured visits (100 per explorer, including original seven-page routes and packed stories) must produce less than 3 MiB total serialized explorer state and each notebook must export/import through the actual existing limits. Test actual save/reload through the existing store. Never evict old visits to meet this budget. This does not promise unlimited storage: keep the existing visible quota-failure warning, in-memory progress and download path, and verify a quota-failure fixture preserves them. No source-deduplication registry or new storage backend is required.

The exact internal field names and pure helper placement are implementation choices. Prefer the existing core/UI conventions and one small source adapter. Any shared route validation must check only the saved shape and captured route linkage, never current catalogue membership; no generalized migration framework is needed.

## Interaction and notes

Normal current visits look and play as before. Recovery is a short focused turn, with “Start a fresh visit,” “Back to the Paris map,” and a Grown-up notes link. State plainly that earlier work remains saved. Do not show today's answer choices beside legacy indices. Preserve a reachable way back and do not gate recovery behind a math question. Use existing 44px controls, keyboard focus and responsive styles; no mouse-only action.

The notes show legacy visit identifiers and position-only responses with an explicit unavailable-wording explanation. Invalid values may be summarized as unreadable while their raw JSON is retained in the existing progress export. The entire export already carries visit objects; avoid a second parallel archive unless an existing loader would otherwise delete the only copy. Saved source used for observations must survive completion and changes to current content. Do not relabel an old reading focus, helper answer or result on load.
