## Purpose and boundary

Sentence Bridges109 joins two whole clauses with and/because/but. Sentence Spotlight403 changes voice inside selected action clauses. Neither lets a child attach a relative clause to a noun and compare which thing it describes. This increment extends the existing `#loft/bridges` visit with a second mode, **Which One?** It changes an actual sentence diagram rather than adding a recognition quiz. Six original two-figure scenes, twelve authored attached versions and six base sentences make the interpretation explicit. The child moves a detail, sees the linked noun/figure and compares wording with fixed scene facts and a reader's purpose. Both attached versions remain tryable; the bridge-picture case has two scene-consistent readings serving different requests.

No new destination, profile, saved root, learning record, level, lock, score, streak, parser or original-prose grade. This visit remains ephemeral as109 already is. Trials for each new case and both modes wait while the child pages inside this visit; leaving the route, reset or changing explorer clears them. Visible copy explains this. No claim of retained work in Notes. Existing109 joins, three scenes, Undo and narration retain their own exact content/semantics.

Spec49 §5 encounter: four short elected teaching cards, the separate duck/swan four-part model, supported movable-clause practice, different nouns/traits/reader purposes, then human-drawn or spoken comparisons. The model uses a different event from all6 cases and never fills the child’s trial. Help/navigation are ephemeral views, not evidence of independently-read material. These are annotation/interpretation opportunities, not full relative-clause production. All scene facts and language are original fictional models.

## Source and pure model

New `dist/sentence-details-content.mjs` exports `detailCopy`, `detailTeaching`, `detailModel`, `detailScenes` (id/title index) and detached `detailScene(id)` factory (null for unknown id). Runtime factory/copy equals the independently reviewed finite JSON, checked once before qualification rather than a permanent prose-sync gate. Original simple SVG schematics are rendered by the UI, with no remote art/font/API dependency. Captioned features are authoritative; icons must depict those features or stay decorative.

Each scene owns `{id,title,context,purpose,clause,entities:[left,right],base:Token[],trials:{[entityId]:{tokens,meaning,sceneNote,purposeNote}}}`. Each entity owns `{id,text,label,kind,feature:{icon,text}}`. Current kinds: parcel/crate/courier/gardener/kitten/bunny/basket/stool/lantern/boat/book/map. Feature icons: star/plain/stripes/empty/spoon/circle/triangle/moon/bridge. They are a small original illustrated vocabulary, never learner identifiers. Every caption remains visible, so no outcome depends on color or picture recognition alone.

Tokens are complete authored literal segments, `{text, noun?:entityId, detail?:true}`; preserve all leading spaces and punctuation. Each base has both noun tokens once and no detail. Each attached trial has both noun tokens once and exactly one detail token immediately after the chosen noun. Joining token.text yields the exact current sentence. The detail token's trimmed text equals scene.clause, but no runtime English parser or case-changing generator is used. Interpretation and scene/purpose notes are authored strings, not inferred or scored. Semantic correctness requires independent finite grammar review; token-shape checks alone cannot establish it.

New `dist/sentence-details-core.mjs` exports:
- `initialDetails()` → `{caseId:firstId,drafts:{}}`.
- `changeDetails(state,action,value)` → detached changed state or null for invalid/no-op.
- `detailsPresentation(state)` → `{scene,anchor:null|entityId,tokens,sentence,meaning,sceneNote,purposeNote,canUndo}` or null for invalid state.
- `detailsNarration(state,view)` → current task wording plus only the elected visible teaching/model parts.

Drafts are visit-only keyed by the6 known scene ids. An absent draft reads `{anchor:null,previous:null}` without materializing it on view. A draft is `{anchor:null|own entityId,previous:null|{anchor:null|own entityId}}`. Unknown case ids, wrong-case entity ids, non-object/array drafts, invalid anchors or malformed previous objects return null, never throw. No version envelope, migration, hash registry or serialized import is added. Valid unknown extra own state fields can be preserved by cloning; none drives rendering.

Actions: `scene` selects a different known scene but retains every draft/Undo; same scene no-op. `attach` selects one of the current scene’s entity ids; same attachment no-op. `remove` sets anchor null (no-op if already null). `undo` restores previous.anchor, then clears previous (no-op if none). Each attach/remove replaces previous with the prior current anchor; a second Undo is disabled. First attach may therefore undo to no detail. Undo affects only current scene. Trials use factory source and authored versions, never mutable source edits. `detailsPresentation` with no attachment uses base, copy.separateMeaning and empty scene/purpose notes. No visit operation mutates app state, localStorage, Notes or a parent writing draft.

View shape is separately ephemeral: `{teachingOpen:false,modelOpen:false,teachingPage:0,modelPage:0}`. All values wait across mode/case changes in this visit; clamp page indices to their source lengths. Opening/closing panels changes only view. No help/reading/attempt count is stored. The narration function accepts this view explicitly, preventing hidden tutorial/model wording from entering the task's Hear payload.
