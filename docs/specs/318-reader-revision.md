## Compact experience

Add an optional **Try a reader's question** invitation on the note page after the existing writing controls. It is usable with an unfinished or supplied-only note. Explicit activation keeps a before-picture of the current note, freezes the three cards, and opens the first question. It never calls Keep automatically, replaces an existing first-kept note, fills writing, changes plans or marks a task correct. No new record on render/load/import.

Use one compact panel with **My note / Reader's question / Compare versions** tabs. Existing editing controls are the My note surface; do not render a second editor. Keep the active writing-part chooser and the current reader's short question available together. Reader tab has three labeled buttons with reader role, one question at a time, **Return to my note**, and optional Hear. All readers are available without previous keeps or answers. The question is a prompt to reconsider existing parts, not a requirement to type an answer into a new field. A learner can talk or write on paper instead.

**Keep this revision** snapshots the current note alongside the unchanged before-picture. It may keep an unchanged or unfinished draft; explain that keeping is not an assessment. Subsequent Keep replaces only this conversation's latest after-picture. The existing **Keep my case note** remains independent: it still owns first/latest case notes and does not silently become a revision keep. Compare offers a part chooser: show that part's before/after text and modes together, with each snapshot's own provisional plan. Unknown/missing parts are labeled, not invented from today's list. Do not put two full dossiers or answer histories side by side. A before-picture never changes when editing, switching plans/readers, changing the working part or keeping again. A currently edited note may differ from its latest kept after-picture; label the latter as kept, never live. Reuse this same conversation on return; another ledger visit has its own conversation. Do not add a conversation engine or round history.

At320px stack before/after; at820px use two paper columns without horizontal/nested scrolling.44px labeled native controls, visible focus separate from selection, logical headings, no drag/hover dependency. Move focus to the opened reader heading, returned existing writing part, or comparison heading; announce successful keeps/refusals. Details are nonmutating and do not replace focused controls. Retain existing dirty-text recovery and keyboard/touch behavior. Optional Hear reads only the active question or visible comparison, not hidden cards/keys/adult caveats; no autoplay. Native speech is not a pronunciation assessment.

Preserve strings verbatim, including leading newlines and original/supplied modes. Snapshot display uses only its own captured labels and exact rendered text; no regrading or fresh catalogue substitution.

Refactor246's existing rendered-note extraction into one small pure helper if useful; do not change legacy Keep's stored shape or history.
