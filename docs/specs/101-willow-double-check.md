## The new learner action

[Willow Sorting Desk](84-willow-sorting-desk.md) lets a child choose one feature test and trace an if/otherwise branch. Willow Double Check keeps its same four fictional stamp-and-wrap combinations, but asks the child to **read both clues, choose `both` or `at least one`, and observe how that one connector changes a single branch**. A parcel with only one matching clue is the decisive contrast; a parcel with both matches under either connector. The rule always takes exactly one of two supplied baskets. This is a small second Post Office desk, not another delivery, a quiz on definitions, or a general programming environment.

The two tests and baskets are supplied, not editable in this first pack. The child changes only the connector, chooses any of four parcels, optionally predicts a basket, and manually steps **read stamp → read wrap → combine two answers → take one branch**. Always read both clues, even when the first is already Yes. This is an explanatory tabletop model, not a claim about JavaScript evaluation order or short-circuit behavior. Switching connector or parcel resets only the live trace and prediction; prior runs stay as recorded. The child can return to a tested parcel, compare the other connector, and leave at any point. No timer, score, mastery, lock, code editor, NOT, nested condition, loop, real address, or generated source is added.

## Independent saved work

Use a **new optional** `willowDoubleCheck` root, absent until explicit Start. Do not add a field to, migrate, normalize, inspect for grading, or reinterpret any `sortingDesk` v1 source/program/check/kept/trace. The new root is warranted because a two-clue connector and four-step trace have different meaning from v1's single condition; sharing its source or history would silently regrade earlier work. Reuse its existing detached-write, optional-root, notes, and recovery patterns rather than building a second generic machine engine.

The new readable root is `{version:1,source,connector,selectedParcel,prediction,phase,checks,nextCheck,support,retainedRaw?}`. `source` is a complete copied authored pack. `connector` is null, `both`, or `one-or-both`; `selectedParcel` is one of that source's parcel IDs; `prediction` is null, `unsure`, or a saved basket ID. `phase` is `ready`, `stamp`, `wrap`, `combined`, or `result`. Only `ready` may have a null connector. A non-ready phase with an unset connector is unreadable. A result phase reads **only `checks.at(-1)`**, the final array slot created by its Send action. That exact slot must be readable and its parcel, connector and copied source must match the current work; history renders each readable run from its own copied source. Never scan backward to an older matching readable check to supply the current result. If the final slot is missing, malformed or mismatched, preserve any existing slot raw in notes, show “This earlier result cannot be read here,” keep healthy history available, and offer an explicit trace restart without rewriting any slot or other work. `checks` is an array of raw-or-readable records, `nextCheck` a positive safe integer, and `support` contains the two booleans `helpOpened` and `together`. No identity, response prose, external URL, grade or global evidence flag is stored. The route turn is not persisted, so reload starts at Rule and parcel if no detail is in the URL; the saved current connector, parcel and phase remain.

The source admission is structural and own-source, not equal-to-today: plain object, `version:1`, safe `id`, `request`, exactly two distinct basket IDs/labels, exactly two uniquely identified clues `{id,feature,value,label,question}` with one `stamp` and one `wrap` feature and a known value (`star|circle`, `blue|yellow`), 1–8 uniquely identified parcel cards with those finite feature values, `requestRule:{connector:'both'|'one-or-both',then:<own basket>,else:<other own basket>}`, and every named `source.text` line. All IDs match `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`; each shown string, including both clue labels/questions, is nonblank, control-free and at most 500 UTF-8 bytes; the complete JSON source is at most 12 KiB UTF-8. The pair of clue labels/questions are copied for old-source rendering; source validation does not require today's wording, card order, feature values, request connector or IDs. Today's first pack separately checks its exact four rows and copy. Harmless unknown keys remain in raw saved data and are ignored when rendering. All displayed source text is escaped.

Each immutable readable run records `{id,source,parcelId,connector,prediction,stampObserved,stampYes,wrapObserved,wrapYes,combinedYes,branch,actualBasket,requestedBasket,matches,support,practiceOnly:true}`. Its `source` is an independent frozen copy so a later source replacement cannot reinterpret it. `support` is the pre-result help/together snapshot. Validate every result against that run's **own copied** source and connector, including the saved request connector, not today's pack or the current root source. A run whose own source or computed values are malformed stays raw; it does not close healthy siblings, the current rule, or a healthy selected parcel. A run is appended only when **Send one parcel** succeeds; reading clues, combining, predicting and opening help do not create runs. All runs are labeled supplied-rule practice, including fits; neither a fit nor a pre-step prediction establishes independent coding or mastery.

Readable run IDs are positive safe integers and increase in array order; duplicate or out-of-order entries become unreadable raw siblings. `nextCheck` must exceed every readable ID. On append, choose the first safe ID at or above `nextCheck` that is not occupied by **any** saved slot's safe positive `id`, even if that slot is unreadable, and advance `nextCheck`; never overwrite an occupied raw record. If no safe ID **with a safe next value** is available, refuse the append with an actionable notes-download notice while preserving the root.

Preserve unreadable slots in their original relative order and never delete them to enforce the window. An imported root with more than eight readable runs remains readable without silently pruning or rewriting; a new append requires a visible one-at-a-time oldest-readable removal confirmation, then removes exactly one oldest readable run, even while the imported readable count remains above eight. The collapsed history shows the last eight readable runs and summarizes any older readable/imported or unreadable slots honestly; the full JSON download retains every still-saved slot.
