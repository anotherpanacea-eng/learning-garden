# 241 — The Equality Desk

## Problem and bounded teaching purpose

The signed-rates unit solves equations but explicitly leaves one/no/every-solution contrasts outside its scope. This original symbolic bench at `#learn/math/equality` follows it. The town's two surveyors write different rules for the same mark: when do the rules agree? These are numerical expressions, not physical parcel masses. All cases explicitly allow **every real number as x**, including negative numbers and fractions. A solution makes both expressions equal. An identity has infinitely many solutions; `0x = 0` does not mean only x=0. A contradiction has none. Equal outputs for a few tested inputs do not prove an identity; a bounded table without a crossing does not prove no solution.

This is supported practice and an open repeatable investigation, not placement, mastery, a whole algebra course, a graphing engine, arbitrary expression parsing or a new story ending. Existing positive-mass Balance Stall and waiting linear lessons retain their own domains/sources/results. No age, score, timer, lock, telemetry or personal learner data.

## Content and exact model

An expression is `k(ax+b)+c`, where each coefficient is a reduced rational string accepted by the existing `parseLinearNumber`; denominator positive, absolute coefficient at most 12, denominator at most4. The view may omit trivial factors but must retain signed parentheses and distinguish multiplication from concatenation. Each source freezes both expression structures, their numeric representation (display is derived from those frozen operands), its story, teaching/help, answer choices and order, key, exact solution if unique, explanatory feedback and complete equivalence lines. Reject nonfinite/unsafe arithmetic. This is not an expression parser: numeric test/solution inputs use the existing bounded exact signed integer/fraction/decimal parser, not eval; all arithmetic uses reduced integer fractions.

Four freely selectable families, three rotating outcome cases per family:

- **Near twins:** `3x+2=−1` (one,−1), `3x+2=3x+11` (none), `3x+2=3x+2` (every).
- **Open the brackets:** `2(x+3)=x+9` (one,3), `2(x+3)=2x+7` (none), `2(x+3)=2x+6` (every).
- **Half-sized steps:** `(1/2)x+1=9/4` (one,5/2), `(1/2)x+1=(1/2)x+3` (none), `(1/2)(x+2)=(1/2)x+1` (every).
- **Beyond the test table:** `3(x−2)+4=2x+7` (one,9), `0x+2=0x+7` (none), `0x+2=2` (every).

A visit serial rotates outcome within the selected family and selects an integer translation t in −2…2. Substitute `(x−t)` for x on BOTH sides of the base equation; this preserves its type and shifts a unique solution by t. Represent translated terms without inflating bounded coefficients: for example `3x+11` is structurally `3(1x+0)+11`, becoming `3(x+2)+11` when t=−2. Store the resulting source, never regenerate waiting work. These 60 variants are repeatable, not 60 distinct concepts. For one selected family, serials 1…15 enumerate all three outcomes at each translation exactly once: outcome index `(serial−1)%3`, t=`floor((serial−1)/3)%5−2`; then repeat. Across four families there are 60 variants. Choices rotate deterministically per visit; labels are similarly concise: “One number”, “No numbers”, “Every real number”. No generated case is selected from other subjects or inferred learner ability. The family preview states what changes; it does not expose an unstarted outcome.

The equivalence proof shows: original expressions → distribute/collect each side → subtract the right x term from BOTH sides when nonzero → subtract the left constant from BOTH sides when nonzero → divide BOTH sides by the nonzero remaining coefficient, or inspect `0x = d`. Show an explanation for every step. Omit no-op subtraction steps. In derived proof equations render a zero-coefficient right side as its constant alone; retain `0x` on the left of terminal identities/contradictions. Never divide by0. For every solution conclude that both expressions are the same for every real x; for none explain why0 cannot equal a nonzero constant. In unique cases give exact substitution. Numerical steps and feedback are generated once when starting and frozen. Subsequent source validation checks bounded structure and own-source arithmetic/key consistency, never compares to today's family catalog or wording. Proof rows own exact normal forms and typed operations. Start/expand normalize the source expressions. Remove-x subtracts the preceding right m from both m coefficients; remove-constant subtracts the preceding left b from both b constants; divide divides all four coefficients by the preceding left m, which must be nonzero; conclude repeats the preceding residual. Validate each transition, require final normal form to justify its frozen key/solution, and allow coherent older sequences with different lengths up to 12 rather than today's exact row count. Equation text is rendered from the frozen operands (original expression tree on start), not unverified free-form math strings. Explanation wording remains source-reviewed prose, not mechanically proved pedagogy.

## Four open pages and visible task

All pages remain reachable at any time, with large previous/next buttons and named page tabs. A persistent header retains the actual equation, all-real domain, selected family and visit. No drag-only controls, hover-only help, automatic advancement, sounds or video.

1. **Meet the rules:** short surveyor story, definition of solution, one worked counterexample (different from the current equation) and the invitation to test. The equation is the main visual, two aligned color-distinct expression panels with text labels. Explain expressions are rules, not objects with negative mass.
2. **Try numbers:** an exact numeric x input, explicit “Test this number” and preset −2,0,2 buttons which test those numbers. Save the typed input before testing; preset buttons test their own number without replacing a separately typed draft; show both substitution expressions, exact outputs and equal/not-equal in a two-column table. Keep up to 12 tests with their raw input, exact outputs and original equal flag. Tests are observations, not scored attempts. A mismatch is a counterexample to “every”; many matches still need reasoning. An absence of matches says only “none of these tested numbers”. A unique solution outside these sample inputs must stay discoverable through proof. Unsupported syntax shows an instruction without an attempt.
3. **Explain why:** learner-controlled reveal of the equivalence proof, one next/previous line at a time, with the equation retained. Initially only the original line; support reveal is committed before displaying the line. Opening help or a line never auto-checks an answer. Previous/next preserves the deepest line seen separately from the currently selected line. Text alternative contains exactly the currently exposed proof; hidden lines are not accessible prematurely.
4. **Make a claim:** choose one/no/every, and when one supply an exact x. Optional hint, different worked example and ungraded explanation. “Check my claim” stays on the page; unchosen/invalid numeric input gives a correction instruction without a checked attempt. A fitting claim requires choice equal to the frozen key AND, for one only, exact numeric answer equal to its frozen unique solution. A correct witness for an identity never makes “One number” fit; explain that testing this witness does not prove uniqueness. An answer field is ignored for no/every and remains saved if switching choice. A wrong unique value is substituted against both rules; wrong type gets the algebraic contradiction/identity/unique explanation. No fixed wording implies that every tested value was all possible real values. Up to12 check records retain source-owned choices/key, raw choice/number/note and support/proof depth/test history BEFORE the check. First and latest are visible and immutable snapshots; no automatic progression. “Keep this visit” preserves first/latest kept writing and check snapshots, including unfinished visits, without a completion label. Leave/revisit anytime; no finish gate.

Inline support and all shown teaching are acknowledged in grown-up notes. Every check is supported practice; requesting a proof, hint or example remains separately recorded. No claim of independent transfer. Note field max 1200 characters, numerical drafts 40 characters. Typed drafts save on input; save refusal leaves visible words in place, marks them unsaved and blocks leaving the activity, changing explorer or rerendering until restored or saved. Provide explicit “Restore saved words” with confirmation; never silently discard. Normal navigation after saved input must work. No new speech button is required.
