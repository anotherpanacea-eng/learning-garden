Activities do not automatically contribute; the explorer explicitly brings work back to this story.

## Four finite contribution readers

Pure `actTwoCandidates(state,chapter)` returns identified retained work, never initializes a host or calls a mutator. The readers validate only fields actually consumed for a retained-artifact reference, not correctness and not today's catalogs. This is structural recognition of local kept/shared identity, not authentication of imported history or complete host-state repair. No body is repeated in the story panel. Unknown/malformed siblings are omitted from the candidate list and stay raw/exportable; a readable sibling remains selectable. Unsupported host versions supply no new candidates. Already-kept story receipts remain reached independently of later host support, deletion or shelf turnover.

All readers bound traversed containers using the existing overall recovery limits; strings used as identifiers are nonempty ≤160 characters, numeric IDs are positive safe integers≤1e9, titles if consumed are strings≤500. Never use an artifact ID as a prototype path or raw HTML. Existing records need not contain every current case, choice or ingredient. Candidate keys are deterministic serialized address tuples, escaped in HTML and matched against the current pure candidate list on Offer; never eval or hash-register them. Within Coin Counter rounds, omit every item whose positive numeric round ID appears more than once in that array, even if one duplicate has other unreadable fields. Draft and shelf remain separate editions and may legitimately share an ID. Do not add an array index or body hash to turn an ambiguous identity into a receipt. The displayed label is a fixed friendly kind plus a distinct saved ID/version, not a raw source body. A selected missing item is refused without falling back silently.
