# 78 — Returning Supply Orders: a ten can open without changing the whole

**Status: draft for independent specification and content review; no implementation.** This optional Bundle Burrow activity follows the already built [Bundle Exchange](53-bundle-exchange.md) and complements the separately drafted Joining Supply Orders (spec 77, not on main at authoring). It is a narrow two-digit subtraction contrast, not a written-algorithm course, a fluency measure, or a required step before any other destination. The [source audit](../source-audits/78-returning-supply-orders.md) gives the upstream and primary-source boundary.

## The missing move

Bundle Exchange changes the grouping of **one conserved collection**. Joining Supply Orders joins **two** labeled collections and may make a ten from their combined ones. The general Number Garden has a 17 − 8 counter question and other taking-away stories, but no fixed two-digit starting board where a child first sees four tens and two ones, opens a ten **without changing 42**, then returns a specified number of counters **so the table really contains less**. The new activity at `#numbers/return` reuses the original Exchange Table's proportional, countable ten-bundle and loose-counter visual language where its meaning fits. It has its own optional save root; it does not mutate Exchange Table, Joining Orders, broad answers, café inventory or garden seeds.

The story uses **pretend seed counters**, never real stock. Pip's planning table begins with 42 counters: four wrapped tens and two loose ones. A separate store tray receives returned counters and remains visible. The pair fixes the start and the returned ten while changing only the requested loose ones:

| Case ID | Exact request | Return target | Canonical remaining picture |
| --- | --- | --- | --- |
| `return-12` | “Pip starts with 42 pretend seed counters. Return 12 to the store tray. How many remain on Pip's table?” | One ten and two ones | Three tens, zero ones; **30** remain. No ten needs opening. |
| `return-17` | “Pip starts with 42 pretend seed counters. Return 17 to the store tray. How many remain on Pip's table?” | One ten and seven ones | Two tens, five ones; **25** remain. Open one of the table's tens to make enough loose ones. |

The chooser says **“Return 12: two loose ones”** and **“Return 17: seven loose ones”** beside the full question and source picture. Either is open first. A correct typed 25 before opening a ten is a number response, not a completed return or observed regrouping. An opened ten is not yet subtraction; only a move into the store tray reduces what remains. The two trays together always still contain 42 counters.

## Picture and actions

Each ten is a wrapper around exactly ten constituent marks; the wrapper is not an eleventh counter. Opening a ten removes one table wrapper and exposes ten table ones. Making a ten reverses that exact exchange, only when at least ten loose table ones are present. This release permits at most one table ten opened at a time, enough for both cases. The picture may show a two-row ten frame for those ten marks, but the frame is **on Pip's table**, never the returned tray, and no counter exists in both loose pile and frame. A compact phone drawing may stack the source, table and store tray vertically without duplicating marks or requiring horizontal page scroll. Distinct labels and patterns accompany color; every count is readable as text. Every control is native, at least 44 px high, keyboard reachable and focus restored when an action disables.

**Return one ten** transfers one currently wrapped table ten to the store tray, up to the target's one ten. **Return one loose counter** transfers one table one to the store tray, up to the target's two or seven ones. Either order is permitted. **Bring back** reverses the corresponding transfer. Return buttons refuse empty source and target overfill atomically; Open refuses when one ten is already open or none remain; Make refuses until ten loose table ones are present. A refused action does not mark handling or change a draft. **Reset this table arrangement** restores four table tens, two table ones and an empty tray while keeping the raw typed result, earlier checks, support and kept copy. The response can be checked or kept before any move. A separate model line says how many of the target counters remain to return and whether the pictured return is complete. No reward, penalty, lock, real inventory transfer, dragging or timed turn.

The minimal model is `{tableTens,tableOnes,returnedTens,returnedOnes,openTen}`. Initial values are `{4,2,0,0,0}`. For a readable draft, `openTen` is 0 or 1, `returnedTens` is 0 or 1, `returnedOnes` is 0 through the case's 2 or 7, and all five values are bounded integers. The invariants are `tableTens + returnedTens + openTen = 4` and `tableOnes + returnedOnes = 2 + 10 × openTen`. Thus `10 × tableTens + tableOnes + 10 × returnedTens + returnedOnes = 42` for every valid state. The pictured return is complete exactly when `returnedTens = 1` and `returnedOnes = target ones`; it need not demand a canonical remaining grouping. For `return-17`, opening one ten is necessary to obtain seven loose ones. For `return-12`, it is optional; an unnecessary exchange cannot be treated as wrong. Return counts, table counts and the exact source question remain simultaneously visible.
