## Purpose and exact boundary

The repository already has the complete pinned Marble graph and the reviewed, limited activity declarations. `scripts/build-learning-atlas.mjs` validates 1,590 topics, 3,221 directed edges, eight subjects, 54 domains, and currently emits the offline Markdown and CSV. The current runtime fetches a separate 87-topic/92-edge `dist/marble-map.json` for `#map`; the complete catalog is inaccessible there. A grown-up needs to answer: “What does the source graph contain, and which specific encounters have we declared here?” without interpreting that as what a learner knows.

Keep `#map`, its 87-node payload, local observations, child invitations, and all learner notes unchanged. Add a visibly grown-up route from Grown-up notes and one descriptive link below the small map: “Browse all source topics and declared activity links.” The full catalog is never loaded on normal child routes. Every destination and task remains open. No age, mastery, readiness, score, achievement, learner selection, or recommendation is computed from this graph.

Do not ship or render raw descriptions, age fields, assessment prompts, evidence lists, standards text, or candidate pattern suggestions in this grown-up view; these have not been reviewed as teaching copy. An edge is exactly `{topicId,prerequisiteId,strength}` where strength is `hard` or `soft`; keep the source direction and do not infer transitive edges. ## Browse and topic turns

`#atlas` opens a plain catalog. Native search input matches topic name or exact/partial ID case-insensitively, with a trimmed maximum of 80 characters; it does not search raw descriptions or suggest a learner level. Native Subject and Domain selects start at All; Domain choices belong to the selected subject, or all 54 uniquely labeled `Subject / Domain` pairs when Subject is All. Changing Subject resets Domain to All. An optional checkbox reads “Only topics with a declared link.” All active filters combine with AND. The count reports matching topics and the loaded source-topic total. Zero results says “No topics match these filters.” with “Clear filters”; clearing restores All subjects, All domains, an empty query, the unchecked link filter and page 1. Sort by subject, domain, name, then ID, with a fixed 20 rows per page and Previous/Next controls. Each row has topic name, source ID, subject/domain, and either “Declared link” or “No declared activity link”; the title opens `#atlas/<topicId>`. No giant graph drawing or 1,590-node DOM.

The result page is a simple index, with the current filter and page held only in module memory for this atlas visit. Before following a topic, retain one in-memory results snapshot and its originating row ID. Going into a topic and using “Back to results” returns to that filter/page and focuses the originating row (or the results heading if it no longer exists). Neighbor browsing keeps this same results snapshot; it does not create a stack of result filters. Leaving the atlas, switching explorers, importing, or resetting clears the filter state; direct `#atlas` opens unfiltered. Browser Back/Forward uses ordinary hash navigation. Returning from a topic to `#atlas` in the same uninterrupted visit restores the index snapshot; entering `#atlas` from outside the atlas starts a new unfiltered visit. The small-map/notes exit links are always available. Browser Back from a topic may revisit the previous topic; it must not be replaced by “Back to results.” Search edits reset page to 1. No local storage, notebook field, or history entry is created for a filter change. A direct `#atlas/<valid-id>` deep link loads the topic with no prerequisite visit; its Back link returns to unfiltered `#atlas` if no in-visit result state exists. Unknown/retired ID shows “That source topic is not in this pinned catalog,” with “Browse all topics” and “Back to the small map.” Never substitute the first topic.

The topic turn shows the source title and ID, subject/domain, then “Declared Learning Garden encounters.” Show each reference kind in plain language: “Authored task,” “Scoped practice,” or “Supplied explanation.” Show its `gameName` and exact `scope` to say what was offered and what remains outside it. A verified route can offer “Open this activity in this app”; that link means the route exists in the **current built app**, not that an external deployment is current or that the topic is mastered. `built-local` is not itself a reason to suppress a real route. Before implementation review, enumerate distinct reference routes and browser-open each against this build; a broken route blocks release rather than silently becoming a false activity link. For zero references, show: “No activity link is declared for this topic. The source connection can still help plan a future lesson.” Never add a link merely because a candidate pattern or related topic exists.

Below encounters, show direct **“Builds on”** edges for this topic and direct **“Used by”** edges that name this topic as prerequisite. Each linked neighbor keeps the original strength: `hard` renders “Source foundation link,” `soft` renders “Source helpful link.” Explain at the top: “These are source relationships for planning, not locked steps or a test of what someone knows.” Direct neighbors are alphabetized by displayed name then ID; zero lists say “No direct source links in this direction.” Link every neighbor to its own `#atlas/<id>` and preserve a usable Back path. Do not automatically expand transitive chains, call a dependent “next lesson,” or imply a soft link is required. There are at most nine incoming and 15 outgoing edges at the pinned base; native `details` may fold the longer list, but every direct link remains reachable by keyboard.

The footer contains exact source/license attribution: “Marble Skill Taxonomy v1 © Generative Spark, Inc. (Marble), pinned at `<commit>`”; link the pinned source and ODbL 1.0 database and CC BY-SA 4.0 source-text licenses. Say: “Topic names and source links come from Marble. Activity scopes are Learning Garden declarations. Neither is a course completion or learner assessment.” The adult atlas preserves exact source titles. Its note says “Age suffixes are upstream topic titles, not an age assignment, prerequisite or access rule.” It ships no separate age-range fields, age filter or placement/gating rule. The app's MIT license does not replace the two Marble layers. A link to the offline full topic ledger may point to the repository file for authors, but it is not required in the runtime view.

## Loading, focus, and exits

The app requests `./grownup-atlas.json` only after rendering `#atlas` or `#atlas/<id>` with the pinned ID syntax (`mt_` followed by letters, digits, `_` or `-`). Malformed paths, decoded separators and extra segments show the unknown-topic state without fetching; valid-looking absent IDs need the loaded catalog to resolve. Resolve IDs exactly as pinned, decoding once; do not case-fold a route ID or use arbitrary IDs as HTML selectors. The atlas renderer accepts the catalog and ephemeral browse state, not a learner notebook. The atlas branch neither calls task exposure/observation hooks nor saves state; check shared render hooks so an atlas visit does not accidentally create learner evidence. The first visit displays “Loading the full source catalog…” with “Back to the small map” (`#map`) and “Grown-up notes” (`#notes`) links; successful JSON is checked for this version/pin, array/object shapes, unique topic IDs, complete pinned counts, valid edge endpoints/strengths and valid reference topic IDs/kinds/nonempty scopes/same-app routes and held in memory for this tab, not per explorer. If fetch, parse, version, counts, or reference/edge IDs fail, show “The full atlas could not load. Retry, or use the small learning map.” with Retry, `#map`, and Grown-up notes links. Do not fall back to the 87-topic slice while labeling it full. A request token/abort guard prevents a response from repainting another route or explorer chooser. No fetch is made for ordinary home, notes, child map, or other activity routes; the existing small-map fetch remains as it is. Reopen after a successful visit may use the memory cache. Saving off, import, and reset neither alter the catalog nor write an atlas field. If the active explorer changes during load, the new route gets a fresh visible page; old callbacks are inert.

After navigating to a topic, focus its heading. Search retains input focus/caret when filtering; native selects and the checkbox retain focus. A polite live result count announces changes without moving focus. Previous/Next move focus to the results heading. Clear filters focuses Search. Do not replace a focused input node on every keystroke. Following a direct edge focuses the new topic heading. Retry focuses the loading/error status, then the topic or index heading. Every button, link, select, checkbox label and summary has a 44px touch target, text at least 16px, visible focus, no horizontal page overflow at 320/820, and usable keyboard order. Wrap long names and IDs; use a single column at 320 and a filter shelf plus results at 820. Search has a visible label and `maxlength=80`; statuses are announced, decorative marks are hidden, and no color alone distinguishes link kinds. No motion or new external font request is needed. Use the existing forest/cream Garden vocabulary as a quiet **field index**: one strong title and thin section rules, compact subject/domain labels, and a clear subject shelf rather than a network diagram. The [mock](assets/108-grown-up-learning-atlas.html) uses real pinned sample names/IDs and original interface copy; its index/detail previews are design examples, not runtime output or evidence.
