## The small missing action

[Bundle Exchange](53-bundle-exchange.md) keeps one collection fixed while its grouping changes. [Joining Supply Orders](77-joining-supply-orders.md) joins two source-owned collections, and a learner can fill a frame, wrap ten, and propose a total. Neither lets a learner **move the meaning of that pictured new ten into an aligned written sum**. This optional Join turn makes that correspondence visible: the source addends occupy tens and ones columns, a ten made from ones is shown as **one ten in the tens column**, and the learner places the supplied result digits only when the picture supports them. The learner can lift the digits and undo the grouping. This is guided representation work, not a typed-total quiz, a general column-algorithm course, or a test of independent calculation or handwriting.

Add a link **“Write what this joining picture means”** inside either started Join case, leading to `#numbers/join/ledger`. A direct deep link with no started case shows the existing two numeric case choices and a **Start this order** action before showing a source picture. Starting is an open selection, never a correctness gate. This *new ledger chooser* must preflight its Start transaction as specified below; it must not call the old Join Start binder and then attempt exposure preflight after the case has already been saved. **“Return to the joining table”** goes back to the saved Join model at its exact earlier grouping. The ledger makes a separate, temporary picture from the same frozen `joiningOrders` case source; it does **not** move a counter, edit the proposed total, change support, create a Join check or Keep, or overwrite the saved Join model. Its own picture resets on case change, route departure, explorer change, import, reset or reload. Within `#numbers/join/ledger`, steps and undo actions remain available until then. A short notice says: **“This is a fresh writing picture of the same orders. Your joining table stays as you left it. This writing picture starts again when you leave.”**

This increment uses the **two existing Join sources**, not a third catalog or a new saved-root version. The frozen current case supplies its `id`, title, request, operands and total. Keep the complete original request visible by a compact native disclosure; the main panel identifies Pip and Dot, states the same operand numbers, and has a link back. Do not re-create the source from today's title or prose, revise historical checks, or treat a previously typed correct total as a completed ledger. A malformed/future Join root uses its established read-only recovery and notes path; the ledger must not bypass it.

The little written **“+1 ten from ones”** is an annotation for the *same* new wrapped bundle, not another bundle to count in the picture. Keep one shared whole quantity per case through every action.

## One reversible picture and one aligned ledger

The route has two open, freely chosen turns: **Picture** for grouping controls and a larger countable picture, and **Write** for the aligned ledger and digit controls. They share the *one* transient state below; switching turns neither advances nor undoes a mathematical step. The Write turn keeps a compact, **still countable** view of the *current* grouping immediately above or beside the aligned ledger and its controls. Its caption identifies these as the same counters, not a second supply. Only one countable picture is visible in either turn. Picture starts open on entry; Write is available immediately, even with separate orders and blank result cells. Both turns have **Hear this step** for their current visible caption; neither requires speech or a correct response to enter. The turn buttons and title give a deliberate keyboard focus destination when switching. A route revisit rebuilds the Picture turn at `separate,false,false` from the saved current case source, never from the saved Join working model; the ordinary Join table retains that saved model without moving any counters as the learner switches turns here. The complete frozen request and a compact source label remain reachable on both turns, with a photo-free source disclosure instead of a repeated tall introduction.

The card has persistent **Tens** and **Ones** headers, a Pip row `2 | 4`, a Dot row `+ 1 | 3` or `+ 1 | 7`, a rule, and initially blank result cells. Digits stay in fixed place-value columns at all widths, never as a single unaligned text string. A screen-reader description states both operand rows, the current picture grouping, whether a new ten exists, and which result cells are still blank. The picture has individually countable marks plus text totals; colors alone never distinguish origin. No source mark is duplicated in a result row or annotation.

Transient state for the current explorer and case is exactly `stage: separate | joined | wrapped`, `onesPlaced: boolean`, `tensPlaced: boolean`. Initial state is `separate,false,false`. The only transitions are:

1. **Join the ones** moves the two source sets of loose ones into one working tray; the original three tens remain pictured. `separate → joined`. **Separate the ones again** reverses it only while the stage is still `joined` **and** both written cells are blank. A wrapped ten must be unwrapped first. The control is disabled or absent at `wrapped` and cannot silently discard that grouping.
2. In the eleven-ones case only, **Wrap ten of these ones** moves the named four Pip and six Dot marks into one ten-mark bundle, leaving one Dot mark. `joined → wrapped`. **Unwrap the new ten** returns those same marks to the ones tray only while both written cells are blank. In the seven-ones case the wrap control is absent or disabled with **“Seven ones cannot fill a ten.”** Do not make a ten automatically. A joined eleven-ones tray cannot put `11` into a single ones-digit cell; wrapping is needed before written result controls enable.
3. **Place the ones digit from this picture** reveals 7 for `steady-orders` at `joined`, or 1 for `full-frame-orders` at `wrapped`. It uses the current count of unwrapped ones, not a typed answer. **Lift the ones digit** reverses it only after the tens digit has been lifted. The source rows stay visible.
4. **Place the tens digit from this picture** enables only after the ones digit is placed. It reveals 3 from the three original tens, or 4 from the three original tens plus the new one. In the exchange case, a small, text-labeled **“+1 ten from ones”** points from the pictured new bundle to the tens column. **Lift the tens digit** hides it. Only after both cells are placed does the full equality `24 + 13 = 37` or `24 + 17 = 41` appear as supplied model writing. It is never stored as the learner's independent answer.

Refused transitions leave both DOM and transient state unchanged and give a specific nearby status. The controls and notes above can be derived from the three fields and fixed source values; no learner input parser, history, score, per-action record or schema for this transient picture is needed. The source-order sums and per-origin constituent counts remain invariants. In the exchange case `4 Pip ones + 7 Dot ones = 4 Pip + 6 Dot in the new ten + 1 Dot loose` and `2 Pip tens + 1 Dot ten + 1 new ten = 4 tens`; in the steady case `4 + 3 = 7` and `2 + 1 = 3`. Every enabled transition is reversible in a visible order, and none creates/destroys a counter. It is acceptable to lift written digits before unwrapping; it is not acceptable to leave a written 41 on screen while the ten is unwrapped.

Use native buttons at least 44px high, no dragging, and the app's existing `hearButton`/local narration. **Hear this step** reads the current turn's stage caption, then the optional written line if present; it never claims a child explained the method or that speech played. A fresh stage update or turn switch stops earlier speech under the existing render lifecycle. After a successful action, focus the corresponding still-enabled inverse action or the current stage heading/status; if an action disappears or becomes disabled, move focus deliberately. The source disclosure, Picture/Write turn controls and back link work by keyboard and touch. At 320px there is no horizontal page overflow, and the ledger columns stay visibly aligned with sufficient space for the full **“+1 ten from ones”** label outside the digit cells. The compact current picture, ledger and digit actions form one short Write turn, including wrapped and finished states. Rendered mock frames include joined 11 ones and wrapped/partly written/finished states at 320 and 820.

A started Join case already has the source root; direct ledger entry first asks the user to start either case through the ordinary Join path. Report only these exact finite signatures when both the canonical pictured grouping and its number are actually visible: `bundle:0:2:4` and the selected `bundle:0:1:3` or `bundle:0:1:7` for separate operand cards; `bundle:0:3:7` for the steady case only when the written result 37 is visible with its three tens and seven ones; `bundle:0:4:1` for the exchange case only when the written result 41 is visible with its four tens and one one.
