## Small useful release

Add one new Paris rooftop story, three passage lengths, two tasks per length: textual evidence, then arranging three event cards in story order. It joins the existing least-encountered story rotation, with an openly available invitation on the Paris map so it can be tried immediately. Existing stories, node IDs, routes, observations, café/science/math records and privacy controls remain intact. No external content upload, live generation or schedule.

Authors add a plain-data ES module under `dist/packs/` and register it in `dist/packs/index.mjs`; no story-engine edits are needed for more packs using supported formats. A small pure compiler validates all registered packs before exposing their generated catalogs, tasks and helpers. The existing six stories stay in their current module. New generated nodes use the established `paris-explore-` IDs/metadata and frozen two-task-plus-postcard routes. A failed pack must not partially register nodes or mutate the original catalog; packaging validation must fail with useful locations. Use a trusted local source module, not runtime user-supplied JavaScript. No new framework, persistent registry, server, or authoring UI.

## Data contract

`{id,version:1,title,stories:[{id,destination,title,passages:{1:[sentences],2:[sentences],3:[sentences]},questions:[question,question],connections:[{topicId,label,scope}]}],helpers:{key:helper}}`. Questions use `type:'mc'` (choices + integer answer) or `type:'order'` (three unique items in their correct order; omit answer), plus existing task title/readingSkill/prompt/hint/explanation/talk/helper fields. Helpers use existing small text-choice examples. Validate destination, unique pack/story/task IDs, version, complete three variants, nonempty connected sentences, both question types, choice keys, exactly three distinct order items, helper references/keys, text fields, and collisions with existing or other packed stories/nodes/helpers. Render all text escaped; no HTML in content required. Pack metadata is generic and public. A CLI `node scripts/check-story-packs.mjs` validates installed packs and reports counts; it performs no network calls or writes.

The compiler creates six tasks for this story, retaining the same passage per question pair and different passage IDs per variant. Allowlist authored fields and reject reserved overrides of generated IDs, links, type/kind/entrance, practiceOnly and reading metadata. Order tasks expose the six possible arrangements as internal numeric answer choices so existing numeric attempt records, notes/export and conservative adaptation can remain compatible. Use one stable lexicographic permutation numbering for normalization, submission, rendering and export, with canonical [0,1,2] at index 0. Their child UI shows only shuffled cards and selected positions, never a multiple-choice list of permutations. Provide a stable non-answer starting display order. Every task remains practiceOnly; second question is rereading and cannot provide new-story advancement evidence. Content length bands remain approximate short/medium/longer, with no grade/level claim.

## Tap-to-order behavior

Begin with empty three-position answer slots. Tap a card to append it; selected cards cannot be added twice. A visible Remove control permits correcting the arrangement, and Clear starts it again without recording an attempt. Persist the partial array of card indexes in the existing draft. Editing the arrangement does not count as a submitted attempt. A core submission function derives the numeric answer from the current complete array; malformed/partial/duplicate/out-of-range data must not become an answer or advance. Lock editing/submission after correctness, like the existing choices, so stale success cannot advance a changed arrangement. Record each submitted arrangement as one numeric attempt, retaining human-readable arrangement strings in observation choices. Show neutral feedback and allow another arrangement, hint, smaller example, explanation, skip, or pause. Read-aloud announces the source, question, and displayed cards, not the internal permutation choices. It stays optional and recorded before playback. Sentence focus, reading/method reports, helpers, save-off, reload and export work as before.

Use native buttons and an ordered selected list, descriptive card/remove labels, a count/status message, at least 44px tap targets, visible keyboard focus, and keyboard-operable actions. Rerender focus goes to a useful available card, removed card, or submit when full. Announce changes without autoplay audio; no mouse drag or motion is required. A new-story shortcut uses an explicit storyId option validated against destination, without changing least-seen defaults or overwriting a waiting visit. Continue/restart choices retain the existing explicit switching confirmation.
