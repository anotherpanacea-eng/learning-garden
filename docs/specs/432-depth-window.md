## Exact model and operations

New pure `depth-window-{content,core,ui}.mjs`, CSS and focused tests. Work has exactly the functional fields `{level,a,b,width}`: integer waterline height `level` in0..6 meters above the fixed bottom; integer probe heights `a,b` in1..6 meters; width enum `narrow|wide`. Default `{level:5,a:4,b:2,width:'narrow'}`. Two dots mark pressure-reading locations, not physical bodies drawn to scale. Seven levels × six A heights × six B heights × two widths =504 finite setups. Do not clamp/move a probe when the waterline changes. Edits set one field explicitly, preserve the rest, reject invalid fields/types/ranges/widths and return no-op for unchanged values. No timer, simulation of filling or automatic advance.

Model assumptions: open rectangular tank, still fresh water, constant density1000 kg/m³ and gravity9.8 m/s². Air pressure at the water surface is the reference and is not numerically estimated. These are selected teaching assumptions, not a real-water measurement. Extra water pressure in kPa is9.8 × depth in meters. Compute `pressureTenths=98*depth` with integer arithmetic; display `pressureTenths/10` without binary rounding artifacts, omitting a trailing .0 (490 displays49, 98 displays9.8), consistently in tables and speech. This is **gauge pressure**, extra relative to air, not total pressure. Same depth in this water has the same gauge reading, independent of horizontal position/tank width.

For probe height z:
- z<level: `status:'water'`, `depth=level−z`, positive `pressureTenths`.
- z=level and level>0: `status:'surface'`, depth0 and pressureTenths0. This is a real zero relative to air, not no pressure at all.
- z>level (including level0): `status:'dry'`, depth and pressureTenths **null**, not negative values, zero or a false measured water reading. The tool offers water readings only. With level0 both dots are above an empty tank.

Controls on Work: native **Waterline above bottom**, **Gauge A height above bottom**, **Gauge B height above bottom**, **Tank setup: Narrow/Wide**. Values have meters in option labels; changes return focus to the changed select. These are independent settled setups. Switching width while holding level fixed represents a differently filled tank, not conserved water stretched sideways; no volume/amount number is supplied. No material flows or appears in an animation. Work readouts always show each height and, when available, its depth and gauge reading. A separate depth bracket joins the surface to each wet/surface point. Numeric readings are supplied model support, not child answers or instrument-skill evidence.

**Pin this setup** stores a private detached copy of the four work fields. Subsequent edits do not change it. With a pin, label **Replace pinned setup**; replacement is explicit. **Compare with pinned** opens a separate page; without a pin it is disabled with a reason. Comparison shows the original pinned settings/readings and current settings/readings as separate HTML tables at the same units, including dry/null versus surface0. No hidden canonical answer, correctness judgment, automatic normalization or averaged missing reading.

Comparison explains which of the four fields changed. Exclusive classification: no changes; width only; level only; exactly one of A/B height only; multiple changed fields (including both A and B). For no changes say **These settings are the same.** Width-only copy is availability-aware: both locations dry → **Width changed. Both locations still have no water reading.**; exactly one dry → **Width changed. Gauge {available} keeps the same depth and reading; Gauge {dry} still has no water reading.**; both available, including surface zero → **Width changed while both depths stayed the same. This model gives the same pressure readings.** Level-only copy has explicit precedence: current level0 → **This tank now has no water. Neither location has a water reading.**; otherwise both current locations dry → **The waterline is below both locations. Neither has a water reading.**; otherwise pinned level0 → **This setup now has water; the gauge heights stayed fixed. Check which locations are in water or at its surface.**; otherwise → **The waterline moved while the gauges kept their heights. Compare depths where water readings are available.** Exactly one A/B height → **Only Gauge {A/B} moved. The other location stayed fixed as a reference.** Multiple → **More than one setting changed. We can compare these setups; to investigate one change, hold the other settings steady.** Current and pinned tables always give each location’s own status.
