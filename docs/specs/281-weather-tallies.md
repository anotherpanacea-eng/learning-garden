## Teaching and boundary

At `#almanac/weather`, report one chosen condition noticed today; at `#almanac/tallies`, turn a frozen list of reports into grouped-fives tally rows. The new behavior is collecting reports across real device dates and constructing categorical counts, rather than graphing two supplied measurements. Reported weather, invented practice, the child's placements and source comparison are separate. No measured weather, forecast, exhaustive condition record, climate claim, correctness grade or skill update.

Five shared codes/labels: `sun` sunny, `clouds` cloudy, `rain` rainy, `wind` windy, `snow` snowy. Conditions can coexist; this record holds the one the explorer chose as most noticeable at look-time. Fixed categories are declared before collection. No location, weather fetch, automatic observation, name, free text, microphone or photo. Looking is optional; no note is different from any category. Existing Field Kit weather outcomes do not become weather reports.

One weather page and one source→count→compare/keep sequence. No moon, minibeast, temperature entry/conversion, hemisphere/season writer, pictogram, bar graph, assessed most/least or story adapter. Existing optional temp/unknown fields remain untouched. Every destination stays open; calendar gaps never nag. A brief four-marks→crossing-fifth demonstration teaches grouping; it is a diagram, not another dataset or test. Optional parent talk asks about the child's own rows and acknowledges ties, without recording a response.

## Construct, compare, keep

`dataDesk` remains an optional array, absent until explicit sheet creation. New bounded sheet:

```
{kind:'weather-tally',version:1,id:'weather-tally-N',source,
 placements:[sourceCategoryCode,...],support:{teaching:false,narration:false,together:false,feedback:false},
 checks:[],kept:null, revisedFrom?:id}
```

Allocate N from1 beyond every own `weather-tally-N` ID encountered in raw entries; scan for collisions, safe positive≤1e9. Count all array entries against24-sheet creation cap; preserve unsupported/imported extra entries, refuse at cap. No root-wide current/next field or automatic sheet selection. Session navigation chooses a stable sheet ID; ambiguous duplicate IDs are retained read-only, not chosen arbitrarily. Other supported unique sheets remain open. All readers tolerate malformed sibling sheets/checks/kept values; unsupported `dataDesk` root blocks only this writer, not weather.

One source day appears at a time. Tapping any row appends its code as one placement for that next day; the mark belongs to the chosen row even if different from the source. At most source.days.length placements. Counts are computed from placements, never filled from source. Fifth mark crosses the first four; show numeric counts redundantly. Back removes only the final placement and restores that day card. Source title/origin/month/key, next dated/ordinal card and cumulative rows remain visible. Keep meaningful short turns; no long mandatory scroll, drag or timed task. Local selection/pages do not create evidence.

**Compare the rows** is optional even unfinished. Freeze `{version:1,source,placements,counts,expected,complete,matches,supportBefore}`; counts from current placements, expected from this frozen source, complete means placements.length===days.length, matches is complete and all category counts agree. State explicitly that equal totals do not prove every day went into its matching row: this is an aggregate comparison, not per-card sorting assessment. Feedback names differing rows and both counts; if counts agree but unfinished, name how many cards remain. Previous check means support.feedback=true for later checks. Narration, teaching and working-together requests record separately, never certify reading/observation. Open the teaching drawer or narrate sheet content only after committing that support flag through the same preflight; a refusal must not expose the action and then claim its support was absent. These drawer/step choices are otherwise transient, with no automatic audio. No global skill/fact/subject/story writes.

Checks max8 own entries. At cap refuse another check without deleting history; editing/Keep remain open. Saved checks validate source shape, placement list≤31 of its own category codes, maps with exactly those category keys and integer values0–31, boolean complete/matches and the four boolean support fields. They never rerun today's answer rules/catalog or recalculate old outcomes. Unknown/raw checks remain exportable and don't poison healthy checks. Count own raw entries for cap.

**Keep this sheet** works unfinished and freezes `{version:1,source,placements,counts,support}` once, without requiring a check. Kept sheet becomes read-only. **Revise as a new sheet** explicitly clones its frozen source/current placements/support into a new unique sheet, checks=[],kept=null,revisedFrom=oldID; previous sheet/checks remain exact. A malformed nonnull kept value is never overwritten; open a fresh sheet instead. New blank sheet from any selected source remains possible within cap. No automatic replacement or eviction.

## Reader authority and kept action matrix

A supported mutable sheet has kind weather-tally, format version1, unique supported ID, a readable frozen source, a dense placement array of zero through source.days.length own category codes, and support with all four own boolean fields. Unknown fields are tolerated and retained. Missing checks is read as an absent empty list; a new Compare may initialize it, while present malformed checks blocks only a new Compare. Missing kept is read as null, initialized only by explicit Keep. A nonnull kept value, readable or not, blocks mutable placement/support/check actions. Present malformed fields are never reset as a recovery shortcut.

A readable kept snapshot independently requires format version1, a readable own source, dense own-source placements within that source's day count, count map with exactly its own category IDs and integer values0–31, and all four support booleans. These historical counts are displayed as recorded; they are not recomputed to gate readability. The kept snapshot is authoritative for kept display and Revision, even if current source/placements/support are malformed or differ. Current draft and independently readable checks remain raw and exportable. A new revision copies kept.source/placements/support and starts fresh checks/kept; its live tally is computed from those copied placements, leaving the earlier recorded counts unchanged. Unsupported/malformed kept cannot be overwritten or revised; choose another source/sheet instead.

Mutable drafts offer row placement/Back, Compare, Keep, teaching, narration and working-together. Kept sheets offer read-only source/marks/recorded comparisons, Choose other notes and Revise as a new sheet only. They expose no new Compare/help/narration/together controls, so frozen support is not changed or newly claimed absent after an unrecorded reveal. To perform those actions, revise first. Unreadable-kept records offer no mutation and retain raw Notes access; other healthy sheets and source choices stay open when root/cap permits. Repeated true support requests on a mutable draft are real no-ops: reopen/replay without a fresh preflight or identity change. Failed first support preflight must prevent disclosure/speech.

Source version is a positive safe content-version stamp; sheet/check/kept format version1 defines this supported shape. A different positive source content version with the same supported shape remains readable. Historical category rows come ONLY from that sheet's frozen source.categories (one through five rows); the five current weather rows apply only to newly authored sources. Never substitute today's category list or infer per-card accuracy from an aggregate match.
