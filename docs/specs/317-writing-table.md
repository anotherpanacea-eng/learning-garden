## Purpose and boundary

Visitors need to find the bakery's opening times; Dot's reader needs to follow a report across town. Teach grouping related sentences, headings, chronological paragraph order, paragraph breaks and signposts of time, place and numbered reasons. The reader's stated need decides a fitting arrangement. Grouping a report's strips does not teach every possible paragraphing convention or assess independent composition.

Build both proposed first benches: **Paragraph Sort** and **The Linking Word**, with all of 277's sets A and B. Fifteen tasks: one nine-strip sort, one three-paragraph order, three break blocks, four paragraph joins, six three-choice items. A2 repeats break block1; A3 revisits the dialogue convention; joins1–3 repeat B1–3. Mark those related supplied texts as familiar practice, never new independent evidence. No task or bench is locked by results.

This commissions the supplied-text paragraph organization slice of E4-II and paragraph-signpost practice. It offers a bridge toward longer-text reading/writing, not evidence of independently doing either. It does not deliver all277, paragraph cohesion/pronoun revision, research, literary evidence, free writing, Act V, a chapter contribution, Keeper Page5 or an ending. Keep all story and existing letter/loft/desk records unchanged. The title is **The Writing Table**; neither Hollis nor the future page heading appears. The standalone material is drafts from town, not the later Gazette.

## Experience

Exact route `#desk/writing`, reachable from the Keeper's Desk and changing letters. A compact two-bench selector leads to a task shelf. Show one task at a time: reader card, source text, one direct instruction, material, **Check this draft**, feedback, and **Keep this version / Next draft**. Next preserves unfinished material and chooses the next task in the fixed fifteen-task order, wrapping; the shelf always opens any task. Never erase another draft when switching. A kept version is optional and never eligibility for Next. The initial task is the nine-strip bakery report. Familiar tasks say **A draft you have seen** based on retained source family only; absence means unknown, not newness established.

At phone/tablet widths retain the task's source, needed heading labels and working draft together. A long report may scroll within the page, but no task's question/control sits behind unrelated tasks or growth summaries. Do not make nested touch scrolling necessary for the strip board. At320px, stack the three trays with a persistent selected strip summary above the destination buttons. At820px, trays sit side by side. All tap targets at least44px; native buttons/selects, visible focus, headings and text labels, never color alone. Sorting: tap a strip, then a labeled tray or **Put back**. Its selected button remains identifiable after a move. Order: each paragraph has **Move earlier/later** buttons with disabled boundaries; moved paragraph retains focus. Break: toggle one labeled **Start a paragraph here** boundary. Joins/items: three native answer buttons retain their authored order. No drag-only action, typing requirement, timer, score or penalty.

The visible assembled report is the payoff: sentences appear in their tray headings (original strip order within each tray, not a keyed within-paragraph order), order task renders the full ordered paragraphs, break task renders the chosen actual paragraph split, join task renders the chosen opener with the supplied following text. Wrong or incomplete arrangements remain editable and appear exactly as built. Never silently move strips, choose an opener or reset on Check. Show what changed and invite another try. Keep can preserve unfinished work and does not imply the draft fits. A first-kept and latest-kept picture show revisions side by side, not automatic writing marks. Human invitation: **Which part helps the visitor? Try a short report on paper, then ask someone to read it.** Nothing a child says or writes is captured.

## Teaching, content and checks

Finite original text comes from 277's first four teach cards, benches(a,b), sets(A,B) and corresponding help; selected unchanged text and commission additions are in317's companion. Reviewed original drawings may use paper, tray and signpost shapes; no generated/private art or external illustrations required. This is a language construction table; every new check has `supported:true, guided:true`, because the supplied teaching/material is always present. Help keeps actual hint/example/narration/together requests separately. Do not infer independent reading, composition, age, mastery, global ability, placement or a completed topic from a check or kept version.

Sort correctness requires all nine source strips placed under their source-defined heading; order correctness uses dawn/noon/evening; breaks use the stated change/custom; joins/items use the explicit supplied context. Distinguish missing placements from a complete different grouping. Return local per-strip or per-choice explanations; no whole-draft red X. The bakery sentences about crusts and buns describe goods, not opening times; a new visitor arriving does not by itself require a new narrative paragraph. Dialogue paragraphing is presented as a usual convention, not universal grammar. The opener *Meanwhile* is keyed to the explicitly same-time context; *Finally* counts the explicitly last reason, not a clock change. All fifteen full keys, source paragraphs, choices, order and explanations are frozen with a task before response, not looked up from today's catalog when resuming.

## Notebook contract

The proposed277 schema is not live. This commission owns optional `writingDesk` with `{v:1,currentId,records:{[taskId]:record}}`; do not introduce a second competing writing root. A new record is created only by explicit Start/Open of that task, not render/import/load. Each record has frozen `source`, `work`, `help`, `checks`, `count`, and optional `firstKept/latestKept`. Source includes `v,id,family,kind,title,reader,prompt,teach,parts,choices,key,feedback,hint,example` and all source text/order/ids used by that task; each display string≤4000 Unicode code points, maximum12 parts,12 headings/choices/boundaries, each id≤80 ASCII code characters. Task kinds: `sort,order,break,choice`. Source may include an authored `after` paragraph, a `changes` context and up to3 guided `steps`; display and freeze these too. At most64 records; absent tasks stay absent. Creating today's task never replaces an unknown same-id record: offer its retained view/download and other tasks, with no normalize/reset.

Work is `{placements:{stripId:headingId|null}}` for sort, `{order:[partId]}` for order, `{boundary:partId|null}` for break, `{choice:choiceId|null}` for choice. Order always holds a complete permutation of all supplied paragraphs, initially in the authored mixed order; paragraphs cannot be removed, so this task has no blank/partial state. Null choice/boundary and unplaced strips are incomplete, not different. Check ids, bounded counts, unique own ids, source-key references, complete permutation or appropriate selection membership and structural reachability against the record's own source only. Do not compare old keys, lengths, wording, outcome or accepted choices with today's catalog. A readable source with another historical heading/tray count or choice order remains playable within the stated bounds. Missing/unknown fields and unreadable records remain exact/exportable. One unreadable record does not close siblings; an unknown root version makes only this table read-only, with all other games open.

Help: `{hint:bool,example:bool,narration:bool,together:bool}`. Set a requested help flag before revealing/playing it, with the existing importability preflight, not an invented attempt. Each Check retains a deep snapshot `{work,help,outcome:'fit'|'different'|'incomplete',supported:true,guided:true,feedback}`. First Check is immutable. Retain first plus latest23 checks, count saturating at1,000,000; show the retained-history limit in grown-up Notes. Kept snapshots independently capture exact work/help and its most recent check only if that check's work is identical; otherwise label **Not checked in this version**. First-kept is immutable; later Keep replaces latest only. Never regrade kept history on rendering/loading, and distinguish old feedback from a changed current draft. Clear selection is an edit, not reset of history. No timestamps, free text, learner labels, metrics registry or cross-game ability inference.

All mutations use existing clone/candidate/preflight/adopt handling; refused candidate leaves root/current/material/check/support untouched. Actual failed-storage behavior uses the app's existing in-memory work and Notes warning. Use existing shared Notes export/import/reset/save-off and explorer roots; verify `prepareProgressImport` accepts reachable maximum records before shipping. Unknown additive data stays exact through successful actions. A stale route node, detached button, queued speech request, old explorer or imported notebook cannot mutate or narrate the active notebook. Non-mutating details do not save or replace live controls. On opening teach/help and selecting each task, request no speech automatically. **Hear this task** reads marked visible English instruction/source/current preview/help/feedback only, using existing device-local speech, without hidden keys or unshown examples; stop on departure and respect unavailable-voice fallback. No network service.
